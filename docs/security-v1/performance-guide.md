# 注册与公钥登录的独立性能验证（DR-P4.5）

此工具只创建临时合成实例和全新 Designer 页面产物。它不接受数据库配置、真实实例目录或端口参数；不会读取本地配置、已有 security/certs/Vault、启动 9091、安装系统信任或覆盖原 dist。需要 Windows、普通用户终端、项目现有依赖和 Node 24；当前实测版本以交付报告为准。不要同时运行其他验收或压测。

## 重复运行

在项目根目录的普通 PowerShell 逐条执行。首次探索和后续确认都会新建实例，可能需要数十分钟；限流保持开启，必要时会等待下一分钟窗口。进度中的 A/B 是对照组名称，不是两台物理电脑。

```powershell
node scripts/security-performance-check.mjs explore
```

末行必须为 `ok: true`。记录末行 `report` 的完整路径；失败时保留整个目录，修复后重新探索。随后将示例路径替换为此次报告路径：

```powershell
node scripts/security-performance-check.mjs register "C:\Users\Example\AppData\Local\Temp\ModeDB-Performance-Example\performance.json"
```

登记文件 `registration.json` 与探索报告放在同一目录。此步骤核对当前源码、完整样本、原生洪泛及容量结果，登记规则为探索 p95 增加 50% 余量、向上取整到 250ms，最低 500ms；登录上限 20 秒，注册证明上限 15 秒，其他场景上限 10 秒。上限是本次隔离验收的拒绝条件，不是产品 SLA。文件已存在时拒绝覆盖。

```powershell
node scripts/security-performance-check.mjs confirm "C:\Users\Example\AppData\Local\Temp\ModeDB-Performance-Example\registration.json"
```

最后执行 `$LASTEXITCODE`，必须为 0，末行还须 `ok: true`。确认阶段使用新实例、新页面构建和全部固定样本，源码、Node 或产物摘要不一致都会失败。每次改变源码后从探索重新开始；确认超限时保留失败报告，修复问题后重新冻结，不能修改登记文件、删除慢样本、关闭审计或放宽门槛使原失败通过。

## 测量内容及边界

固定次序 A→B→B→A，每块独立实例、相同 1000 行合成数据、两次查询预热。A 使用 registry API 凭据，B 使用软件生成的真实 WebAuthn EC 签名及 Cookie 会话。两组都保留审计和 Windows CurrentUser DPAPI。注册开始/证明在 A 中没有等价操作，因此报告它们的绝对耗时；不把创建 API 凭据当成 WebAuthn 注册。

服务端由独立 Node/tsx 进程加载冻结的当前源码，客户端由另一个 Node 进程驱动 HTTPS；Designer 使用本轮新构建的公开页面字节。它验证该源码执行路径，不代替安装后压缩发行包的性能验收；D31 的安装证据也不能冒充本轮重新安装。

确认阶段 B：注册开始 30、注册证明 30、登录 60、续期 30、1000 行查询 60、10 行批量保存 12、静态页面 30、撤销 30、撤销后 HTTP 拒绝 30。A：凭据创建 30、查询 60、批量保存 12、静态页面 30、撤销 30、撤销后拒绝 30。正常业务并发固定为 1；探索采用每块 3 个身份，确认采用每块 15 个身份。申请/登录按原单源限额等待，未提高限额或伪造代理来源。

每个样本保留端到端、服务端处理、TLS 握手、证明队列等待、保护器调用和 WebAuthn 验证耗时，以及服务端 Node CPU 毫秒与 Node RSS 高水位；报告逐场景 p50/p95/max 和失败数。登录为开始与完成两个请求的耗时之和，不含本地软件签名生成时间。HTTP 服务端计时从 request 事件至 response finish，本机管理计时为实际 OS 身份验证后的管理动作；本机端到端另包含管道与 IPC 往返。TLS 使用仓库明确的公开合成证书、进程内 DNS 和每请求新连接，保持证书验证，不安装信任。端到端减服务端/TLS 的差值还包含客户端编解码与调度，不能当作纯网络 RTT。

资源门槛：服务端 Node RSS 不超过 1024 MiB，单样本 Node CPU 不超过 10000ms，正常证明队列等待不超过 1000ms。CPU/RSS 不包含 DPAPI PowerShell 子进程；保护器的阻塞墙钟时间已计入服务端和端到端。此限制不表示整机资源或生产并发容量通过。

另建原生实例，可信离线准备 1000 条未验证待审申请，然后同时发送 48 个有效结构的注册开始请求；全部须以容量或限流拒绝，拒绝审计聚合计数必须准确等于 48。事先预览仅允许回环的来源规则；收到至少一个响应且其余仍在途时，经真实 Named Pipe 应用规则，必须在 15000ms 内完成。请求结束后确认规则并回滚，核对配置与原值一致；洪泛请求最长 60000ms。它验证满容量与单来源突发期间本机维护可用性，不代表分布式攻击下的生产保证。

注册与登录的公共拒绝审计共用每实例最多 64 项的 FIFO，每项仍独立完成正常持久审计，响应等待审计结果；每项之间让出事件循环，使本机管道可以运行。队列满或存储失败时返回容量错误，不能宣称该拒绝已成功落盘；存储故障仍关闭台账。证明的 4/32 槽和正常准入限额不变。该调度解决了隔离探索中本机维护被连续拒绝审计拖延约 35 秒的问题；它不能限制单次 DPAPI 调用的系统阻塞，也不保证所有类型的分布式洪泛下的维护延迟。

4 个执行槽、32 个排队槽及第 37 个证明拒绝，另由合成 AES-GCM 保护器和受控验签等待验证，实际 WebAuthn 库仍执行验证，维护动作仍执行原权限逻辑。此项明确是确定性队列测试，不冒称原生 DPAPI 下同时完成 36 个认证器或硬件性能。

注册到期维护继续每 30 秒检查未完成申请；过期或已废弃的申请仍及时持久化终态。已经完成且不再可用的挑战是有界垃圾，随后续公开注册操作或重启回收；新申请与该清理共用一次持久事务，清理和注册两条审计均保留，审计容量和写入失败仍整体拒绝。这样避免无待处理申请时后台仅为清理已完成挑战而阻塞 TLS，也避免注册开始执行两次独立 DPAPI 提交；没有延长任何挑战的可用期限。

## 结果与排障

临时目录中的 `performance.json` 保留全部已收集样本和错误结果，`block-0.json` 至 `block-3.json` 是完成块的原始统计；`source-manifest.json`、`candidate-manifest.json` 绑定源码与公开构建。实例目录含合成运行材料，也不应整体上传。交付只复制明确的统计、源码摘要、公开页面字节及检查日志。

`PERFORMANCE_HTTP_STATUS_*` 表示预期业务/拒绝结果不符；`PERFORMANCE_SERVER_METRIC_REQUIRED` 表示观测丢失；源码/产物变化、超时、缺样本、NaN、超出门槛和维护未与洪泛重叠都拒绝成功。保留报告并查看 `errorCode`/`diagnostic`；不要删除真实台账、重建密钥或调整真实网络规则来修复测试。

本项使用软件签名，不测 PIN、生物识别、密钥触摸或 Windows Hello。实际两台 Windows 注册、登录、保存、停用与重启验收属于 DR-P4.6；原恢复演练不能替代它。部署仍须根据目标设备和网络重新测量，不因本机隔离结果宣称低延迟、高并发或生产容量。

本轮隔离结果与原门槛见 [SEC-M7 / D33](../security-v1-deliveries/SEC-M7.md#d33dr-p45-独立性能与本机修复资源保障)；原失败及修复后探索/登记/独立确认均保留。后续设备和源码须重新探索，本轮通过不能替代目标部署测量。
