# 独立接收方密钥与持有证明契约

DR-P4.1 使用已有 `modeldb.migration-key.v1` 的独立 RSA 3072—4096 位接收方密钥（SPKI SHA-256 指纹、RSA-OAEP-256），不使用 WebAuthn 签名密钥、TLS 私钥、实例 IMK 或库 DEK。DR-P4.2 在该登记基础上接入原完整迁移与资产包离线导出，保留原格式、算法及导入边界。

## 信任与操作

只允许专用准确 127.0.0.1 管理监听器上的 OS 配对会话，或已验证 OS 身份的本机通道执行 `registration.recipient.*`。沿用后端 socket、Host/Origin、CSRF、管理期限及预算，不开放匿名或数据面申请入口。管理员必须通过可信渠道核对人员、登记 userId 和独立公钥指纹；证明只说明能使用对应私钥，不证明姓名、设备或硬件归属。未知用户、停用用户/主体、没有 active 登录凭据的用户不能新增或替换绑定。旧解密能力不依赖登录可用性。

普通打开不迁移。管理员明确确认并携带准确总修订，执行 initialize，把已有 V4 原子升级为 V5，新增独立 recipient 集合，保持身份、会话、授权、实例和数据密钥。V1—V3 必须先走既有显式认证迁移。旧 reader 应拒绝 V5，禁止修改版本号回退。关闭注册/登录不删除集合。

## 单次证明

begin 携带实例、总修订、登记 userId、PEM 公钥与 confirm:true。后端拒绝私钥 PEM、未知字段、弱/错误算法、非 RSA、非 65537 指数、重复指纹（包括历史）、认证公钥复用及超过容量的请求，反向批准/替换登录公钥也拒绝复用活动、历史或未到期挑战中的接收方公钥。规范化 SPKI 后生成随机 32 字节秘密。公开挑战绑定格式、实例、userId、随机 challengeId、新版本、前一 active key ID（或 null）、指纹、创建/到期时间。五分钟有效，RSA-OAEP SHA-256 的 label 为这些字段固定顺序 JSON 的 UTF-8 字节；ciphertext 只含随机秘密。

接收方用离线工具导入挑战，独立核对实例/userId/指纹/版本/前版本及期限，再在本机解开受口令保护的私钥。输出 `SHA-256("modeldb.recipient-proof.v1\\0" || label || "\\0" || secret)`。不接受任意密文解密、任意 label 或包解密用途。服务器仅保存该 proof 的 SHA-256，不存秘密、密文、私钥、口令或完整证明。

complete 明确携带 challengeId、proof、实例、最新总修订和 confirm:true。服务端重查用户/主体/active 登录状态、期限、绑定前版本与公钥唯一性；准确比较摘要，在一个原子事务内消费挑战、退役前版本、追加 active 新版本与成功审计。一次有效格式的错误证明会持久消费挑战并记录拒绝；到期/身份失效/版本漂移同样拒绝并消费。格式错误或 CAS 冲突不消费，仍不自动重试。提交故障不报成功，重开列表/审计核查，不能凭错误响应断定未提交。

证明是五分钟内的一次性敏感回执，仅交还可信本机管理员，不进入 URL、Web Storage、日志、错误、证据或业务库。刷新页面丢失下载的挑战状态但不撤销服务端挑战。重启保留有限期挑战，不延长期限，不允许重放终态；管理会话仍须重新配对。

## 历史、替换与恢复

每用户从 1 单调递增版本，最多一个 active。替换由相同流程再次证明新私钥，并明确标注旧版本；管理员可在旧私钥丢失后核验人员再替换，但不能解开旧包。retire 是永久停止新交付资格；无删除/重新启用/原地改写公钥。历史公钥、指纹与时间保留。禁用/撤销登录、换登录凭据或用户停用不删历史接收方材料，也不暗中恢复新交付资格。访问重置会退役 active 接收方并拒绝未完成挑战，历史仍保留；空访问灾备不恢复原登记，应重新核验绑定。

接收方独立保管每个历史私钥和口令的受保护备份，勿提交 Git。服务端不备份这些私钥；新公钥不能解旧包，丢失且无独立恢复接收方则旧包不可恢复。此步骤不重封装、不迁移旧 Vault、不改变备份/资产格式、不提供行级隔离或 TPM 保证。

## 限额与投影

每实例最多 10000 个版本、每用户最多 20 个版本（含退役历史），最多 128 个未过期挑战；begin 清理已过期挑战，未到期终态保留以拒绝重放。列表分页默认 25、最大 100、offset 最大 10000，仅元数据、最新总修订和集合是否初始化，不回传公钥原文、秘密摘要或证明。所有命令严格字段和大小检查，复用管理预算/审计容量；不得以删除历史绕过上限。

## 按已核验接收方离线交付（DR-P4.2）

停机后通过 `security recipient-list` 获取实例绑定的元数据和最新总修订。此命令要求明确配置、实例与当前 Windows 身份，持有独占租约，仅列表、不初始化或迁移。列表同样写审计、推进总修订；分页或其他维护之后必须使用最后一次返回的修订。

`backup-export` / `asset-export` 使用完整五项选择：`--recipient-id`、`--recipient-user`、`--recipient-version`、`--recipient-fingerprint`、`--revision`，另需准确 `--instance` 及 `--yes`。禁止与 `--public-key` 混用、不按名称或“最新版本”猜测。V5 导出必须选择已核验接收方，不能退回裸 PEM；V1—V4 保留原显式 PEM 导出，禁止手改台账版本获取兼容入口。导入不要求恢复源访问台账或在线登录。

导出持有独占实例租约直到发布结束；选取时准确 CAS，验证活动版本、用户/主体 enabled 及至少一个 active 登录凭据；封装后、外部写入前再次检查身份和本次修订。私钥与口令留在接收端。复用原随机内容密钥、RSA-OAEP-256 与 AES-GCM；`modeldb.backup.v2` 的完整受信迁移仍无独立来源签名，`modeldb.asset.v1/v2` 保留独立发布者 PS256 签名和显式指纹信任。它们均未新增登记 userId/版本字段，不证明目标物理主机、授予数据访问权或提供行级隔离。

外部写入之前原子追加 `recipient.delivery.sealed`：准确接收方 id/userId/版本/指纹、包 SHA-256、种类及源库。仅记录非秘密元数据；审计容量或提交失败则拒绝发布。sealed 表示密文已封装并记账，不能当作文件已成功写入；外部文件新建且不覆盖，成功写入/同步后沿用 task.completed。文件尝试写入后出现异常一律 `SECURITY_OUTCOME_UNCONFIRMED`，保留文件、原包、列表及审计核查，不自动重试。该流程不承诺跨文件硬件断电事务。

退役/停用阻止未来交付，不撤回已发包；旧包仍需对应历史私钥。目标使用独立新 DEK 与空访问台账，不导入源用户或授权。完整迁移先暂存再显式 restore：暂存未发布时原流程允许再次暂存，目标已存在则拒绝重复迁移。资产确认摘要绑定目标与现状，旧摘要重复导入拒绝；重新预览后的恢复/幂等性沿用原任务协议，不承诺所有包的全局一次性接收。详细操作见[运行手册第 19 节](device-registration-runtime-guide.md#19-按已核验接收方离线交付dr-p42)。
