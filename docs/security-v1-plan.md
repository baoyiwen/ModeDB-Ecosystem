# ModelDB 安全改造 V1 方案

状态：分阶段实施中；SEC-M1—SEC-M5 已交付，实际状态以里程碑台账为准。本文的目标能力不等于已经全部实现，也不授权删除现有库、轮换当前凭证或修改正在运行的服务。

适用范围：ModelDB 引擎、Server、SDK、Model Designer、Query / Operation Interface、Binding Surface，以及备份、恢复和资产图谱交付。

开发任务状态、里程碑门槛与每次交付记录统一维护在[开发任务与里程碑台账](security-v1-milestones.md)。本方案用于说明需求和技术设计，不另外维护一套研发进度。

| 编号 | 需求                   | V1 交付边界                                                                              | 对应阶段          |
| ---- | ---------------------- | ---------------------------------------------------------------------------------------- | ----------------- |
| R01  | 安装后默认安全可用     | 自动初始化，本机可信配对，不要求手写 Token，无通用默认密码                               | S1、S2、S4        |
| R02  | 凭证与数据加密分离     | 独立实例主密钥、每库数据密钥；更换访问凭证不影响解密                                     | S1                |

| R08  | 黑白名单与限流         | IPv4/IPv6/CIDR、入口分离、拒绝优先、规则到期、可选临时封禁、可信本机修复                 | S4、S5            |

| R10  | 保持备份与移库方便     | 包加密、独立恢复材料、异机恢复、完整迁移；不复活旧凭证，不依赖原机器保护                 | S1、S6            |
| R11  | 支持未来资产交易       | 按资产依赖打包、独立交付密钥、完整性与来源验证、导入预检；不交付源实例秘密               | S6                |
| R12  | 稳定、可解释、可观测   | 目录统一、错误脱敏、缓存不绕过权限、断电/磁盘满可恢复、UI 不闪动、zh/en/ja 与文档一致    | 全阶段、S7 总验收 |

后续扩展：标准外部令牌交换、企业身份联合、完整用户/租户行级策略、外部不可变审计、多节点密钥服务、交易平台。V1 预留契约，但不通过未验证用户头或占位接口提供这些能力。

必须接受的边界：白名单不免认证；IP 不等于用户；直接使用 HTTP 客户端不等于攻击；独立恢复材料全部丢失后无法凭访问重置找回数据；交付后不能靠加密阻止买家复制已解密内容。

## 1. 最终要达到的体验

安全改造需要同时满足三个目标：安装后本机可直接使用；需要时可以管理和重置安全机制；数据资产可以安全备份、迁移和交付。

推荐采用“自动初始化、本机可信配对、凭证与数据密钥分离、资产独立封装”的方案。

| 使用场景               | 目标体验                                                           | 安全约束                                                                      |
| ---------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| 首次安装、本机使用     | 自动创建安全目录和密钥，通过本机启动器打开 Designer 后自动建立会话 | 不要求手动编写 Token，不提供通用默认密码；本机 TCP 请求不能自动获得管理员权限 |
| 后续本机启动           | 自动加载受操作系统保护的密钥，恢复正常使用                         | 密钥不可用时停止打开受影响的库，不自动生成替代密钥覆盖原文件                  |
| Postman / 外部程序调用 | 在安全中心创建指定数据库、指定接口的凭证                           | 使用 HTTPS 和有范围、有有效期、可撤销的 API Token                             |
| 局域网或公网使用       | 明确开启远程访问，配置证书或反向代理，再配对远程设备               | 自动显示 Network 地址只解决地址发现，不代表完成身份验证或 TLS 信任            |
| 更换 API Token         | 在安全中心或 CLI 轮换，调用方更新凭证                              | 不重新加密数据库，不影响 Vault 解密                                           |
| 快速移库               | 导出迁移包，在目标实例验证、预览并导入                             | 接收方使用自己的实例密钥；不复制源实例管理员凭证                              |
| 资产图谱交易           | 导出指定资产范围的独立交付包，按买家密钥封装                       | 交付包不能解锁卖家的其他库、其他资产或后续备份                                |
| 本机身份失效           | 通过有权限的本机管理员或独立恢复材料恢复访问                       | 重置认证不等于找回已经丢失的数据加密密钥                                      |

“全自动”的边界需要明确：自动初始化不要求日常手工管理密钥，但异机灾难恢复必须有一份独立于本机的恢复材料。远程设备首次信任、可信证书和外部备份目的地，也无法在完全没有授权或配置的情况下安全猜测。

本方案重点防范凭证泄露后的横向访问、未授权网络调用、浏览器跨站请求、磁盘或备份文件被单独窃取、误操作和不可信导入包。TLS 保护传输，Vault 加密保护离线文件，权限控制保护在线访问，它们不能互相替代。

已经控制服务器进程、操作系统管理员账号或当前受信用户会话的攻击者，可能读取运行中的明文或调用解密能力；DPAPI 不能解决这类主机完全失陷的问题。本方案也不声称阻止合法接收者复制已经解密的数据。

## 2. 改造前基线与需要修改的原因

以下判断以改造前 Git `07e5393` 源码为准，保留作为改造动因。M1 后的密钥与存储实现见[Vault 契约](security-v1-vault-contract.md)，后续任务状态见台账；本表不是当前完成状态。

| 当前实现                                                                                                              | 影响                                                                               | V1 改造                                                          |
| --------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| `packages/common/src/atlas-vault-secret.ts` 从 `connectToken` 派生 Vault secret；Core 与 AuthoringBridge 依赖这条链路 | 直接换 Token 可能导致原库无法解密；认证泄露也会影响数据密钥安全                    | 独立生成数据库密钥，由专门的密钥提供器交给 Core                  |
| 默认初始化把随机 Token 写入配置；CLI 还可打印 Token、通过命令行接收 Token                                             | 配置、命令历史和进程参数可能泄露长期凭证                                           | 配置只引用安全存储；凭证创建后仅交付一次，支持受保护文件输入输出 |
| HTTP / WS 主要验证同一个全局 Token                                                                                    | 调用者身份、权限范围、过期、撤销和调用归因不足                                     | 建立凭证注册表和统一权限检查                                     |
| Designer 可把长期 Token 放入 localStorage；存在 `VITE_MODE_DB_TOKEN` 回退                                             | 浏览器脚本或构建产物可能持有长期凭证                                               | 短期会话、明确配对、移除构建时生产密钥                           |
| wire codec 包含 XOR 编码以及从 Token 派生的会话材料                                                                   | 不能把这些编码视为标准的网络加密和完整性保护                                       | 远程使用 TLS；新协议移除对自制加密的安全依赖                     |
| CORS 较宽松，WS 未形成统一 Origin 信任策略                                                                            | 浏览器跨站访问边界不完整                                                           | 明确 Origin 白名单、WS Origin 验证、Cookie 场景的 CSRF 防护      |
| 已有发布接口访问规则和部分接口级限流                                                                                  | 有可复用基础，但不能代替全入口身份与权限控制                                       | 保留发布策略，并统一接入主体权限、限流和审计                     |
| 备份把文件以 Base64 放入 JSON；其中 Vault 自身已有加密                                                                | 外层包并非独立的可迁移密钥包，也不具备完整的来源签名；不能简单认定整个库是明文备份 | 增加完整包加密、密钥封装、签名、恢复依赖与验证                   |
| Vault 保存使用临时文件后复制覆盖目标                                                                                  | 复制覆盖不能直接视为断电安全的原子提交                                             | 对密钥、目录和 Vault 更新设计日志、同步与崩溃恢复                |

V1 可以破坏旧的配置、SDK 协议和 Vault 格式兼容性。主路径采用新库重建，不投入复杂的在线无感迁移。但实施时仍需识别旧格式、清楚报错、保留旧文件；获得明确删除指令前，不删除现有测试库。

## 3. 身份、凭证和密钥如何分工

### 3.1 凭证只负责“谁可以做什么”

| 类型          | 用途                                                   | 保存方式                                                |
| ------------- | ------------------------------------------------------ | ------------------------------------------------------- |
| 本机管理身份  | 安装者、获授权操作系统账号通过本机管理通道执行管理操作 | Windows SID / Unix 用户与本机通道 ACL，不靠来源 IP 判断 |
| Designer 会话 | 浏览器日常设计、查询、管理                             | 服务端可撤销的短期会话；浏览器持有 HttpOnly 会话 Cookie |
| API Token     | SDK、Postman、后台程序调用                             | 调用端保存原文；服务端只保存摘要及权限元数据            |
| 设备配对记录  | 确认远程或本机设备的后续会话申请                       | 设备标识、公钥或受保护的续期凭据，可单独撤销            |
| 恢复授权      | 本机安全状态损坏或换机后的恢复                         | 独立恢复材料，仅在恢复流程使用                          |

API Token 推荐格式为 `mdbt_v1_<credentialId>_<randomSecret>`。随机秘密至少 32 字节，使用密码学安全随机源。Token ID 用于查找记录；秘密摘要使用标准算法并做恒定时间比较，不把 Token 原文保存到业务库或日志。

注册表至少保存：ID、名称、创建主体、创建时间、到期时间、状态、授权资源、操作范围、轮换来源和最近使用时间。最近使用时间可以批量更新，但撤销和权限变更必须立即持久化。

不使用无服务端状态的长期 JWT 作为唯一认证方案，避免撤销只能等待到期。V1 优先采用可立即撤销的不透明会话和 API Token。

### 3.2 数据密钥只负责“数据如何解密”

| 密钥               | 用途                               | 轮换影响                                   |
| ------------------ | ---------------------------------- | ------------------------------------------ |
| 实例主密钥 IMK     | 在本机封装各数据库的数据密钥       | 重新封装数据库密钥，通常不重写业务数据     |
| 数据库数据密钥 DEK | 加密某一个数据库的敏感数据         | 需要重新加密该数据库，属于维护任务         |
| 恢复密钥           | 让独立备份可以在本机密钥丢失后恢复 | 更新恢复封装及恢复材料，保留必要历史版本   |
| 导出包密钥 PEK     | 加密一次备份或交付包的内容         | 每次交付独立生成，不与源数据库共用数据密钥 |
| 发布者签名密钥     | 对资产清单与内容摘要签名           | 更新签名身份与信任信息，不用于解密 Vault   |

核心关系：

```text
操作系统安全存储 → 实例主密钥 → 数据库密钥 → Vault
独立恢复材料     → 恢复封装   → 所需历史密钥 / 备份内容
接收方密钥或口令 → 包密钥     → 本次交付包
```

API Token 不参与以上数据解密链。签名密钥也不与认证或数据加密密钥共用。

数据库继续使用成熟的认证加密，例如 AES-256-GCM；随机数、认证标签、版本和密钥 ID 均进入格式规范。认证附加数据绑定数据库实例 ID、数据对象与格式版本，防止把密文搬到不属于它的对象上。密钥封装单独绑定 DEK ID 和所属数据库，避免主密钥轮换必须重写全部业务密文。

接收方公钥封装采用经过评审的标准方案和成熟实现，例如适用的 HPKE / JWE，不自行发明混合加密协议。口令导出使用带随机盐、参数版本和计算成本的成熟 KDF；优先评估现有 Node scrypt 能力。导入器限制 KDF 参数上限，避免恶意包要求无限内存。具体库选择与性能参数在第一阶段定稿。

## 4. 安装后如何自动可用

### 4.1 新实例第一次启动

1. 确定实例 Home 和实际运行账号。默认沿用现有平台路径规则；Windows 通常为 `%LOCALAPPDATA%\modeldb`，服务安装则使用明确的服务账号与实例目录。
2. 对初始化加独占锁，创建实例 ID、受限目录、本机管理通道和安全注册表。
3. 随机生成实例主密钥与必要的独立密钥，使用 SecretProvider 保存。Windows 默认采用当前实际运行账号的 DPAPI 及目录 ACL，不能误用安装时账号导致服务启动后无法解密。
4. 写入不含长期秘密的配置与初始化状态，完成同步和一致性检查后标记实例可用。
5. 默认仅监听 loopback。安装的本机启动器通过受 ACL 限制的 Named Pipe / Unix Socket 证明本机管理身份，向服务申请一次性浏览器配对授权。
6. 启动器打开 Designer。浏览器兑换短期、一次性、绑定目标实例与预期 Origin 的配对授权，服务建立会话。授权不得进入 URL 查询参数、访问日志或长期浏览器存储；前端消费后清理临时地址状态。
7. 安全中心显示“本机安全已初始化”，并单独显示独立恢复材料是否已保存。

全流程不把“第一个访问 HTTP 的客户端”视为管理员。多个浏览器或安装进程竞争初始化时，只有受信本机管理通道可以签发配对授权。

### 4.2 后续启动与异常

正常启动直接解封本机密钥并建立本机配对会话。重启服务不会更换实例身份、数据密钥或 API Token。

以下情况必须明确报错并进入维护状态：DPAPI 无法解封、密钥记录缺失、Vault 认证失败、安全注册表损坏、实例 ID 不匹配。不能自动新建“看起来正常”的空库，也不能生成新密钥覆盖旧密钥。

重装系统、切换服务账号和直接复制整个实例目录，不保证本机保护仍可解封；这类操作走正式迁移或恢复流程。

浏览器单独打开一个地址时，如果没有有效会话，则显示连接或配对页。本机正常安装启动路径可以自动完成配对；开发环境继续手动启动 Vite 时，可以通过本机 CLI 打开配对链接，而不是在前端 `.env` 中放永久管理员 Token。

远程设备首次接入由已有管理员在安全中心批准：先确认目标实例地址、TLS 信任和待授权范围，再生成短时一次性邀请。远程浏览器兑换后获得限定会话，默认不继承实例管理员权限。若需要记住设备，只保存服务端可撤销、绑定该设备且轮换的续期能力；浏览器使用受保护 Cookie，不持有长期全权限 Token。没有任何有效管理员会话时，只能从可信本机通道或恢复流程重新授权，不能开放“无人认领管理员”页面。

### 4.3 恢复材料与自动化的边界

本机初始化可以自动完成，独立恢复材料的保存不强制阻止日常使用。但未保存时，状态必须明确显示“仅具备本机恢复能力，尚未完成异机灾难恢复准备”。

推荐首次配置恢复时生成独立恢复密钥对：本机保留恢复公钥，私钥形成加密恢复包；用户把恢复包和解锁材料保存在独立位置，或交给已配置的外部密钥服务。未来备份和密钥轮换可直接用恢复公钥生成新封装，不需要反复手工输入口令。

新恢复公钥登记后，应为仍需恢复的旧密钥补齐恢复封装；旧备份的历史密钥不能因主密钥轮换而被自动销毁。独立恢复材料更换时，要明确哪些旧包仍依赖旧材料。

若用户没有独立恢复材料，又同时失去系统账号保护和本机密钥，系统无法通过“重置密码”找回加密数据。把恢复包和解锁材料一起放在同一个本机目录，并不能解决整机丢失问题。

## 5. API Token、权限与会话

### 5.1 权限模型

采用“主体 + 数据库 / 资产资源 + 操作范围”的默认拒绝模型。管理接口、通用 RPC、HTTP、WS、批量入口和所有发布接口共用一套授权判断。

| 预设身份       | 默认能力                                                    | 额外授权才具备的能力                           |
| -------------- | ----------------------------------------------------------- | ---------------------------------------------- |
| 实例管理员     | 管理实例、凭证、会话与密钥策略                              | 危险删除、明文导出等仍需具体操作确认与审计     |
| 模型设计者     | 在获授权数据库内管理模型、查询设计和发布版本                | 跨库访问、实例安全管理、数据批量写入及资产交付 |
| 数据操作员     | 在获授权模型内查询和写入数据                                | 模型结构修改、接口发布、密钥与凭证管理         |
| 发布接口调用者 | 调用获授权的 Query / Operation Interface 或 Binding Surface | 通用模型 RPC、系统模型访问、任意字段查询       |

角色只是预设权限集合。导入、数据导出、备份恢复、资产交付分别定义操作权限，避免“可以查到部分数据”隐含“可以整库打包”。V1 不把完整的行级权限、租户隔离策略或复杂企业组织模型纳入首批交付。

SEC-M3 的实际授权粒度与入口矩阵见[统一授权契约](security-v1-authorization-contract.md)：通用 RPC 采用整库读写权限，精确字段访问通过固定完整发布摘要的接口投影提供；具体模型或字段 grant 不会自动变成通用查询过滤器。当前引擎不支持跨项回滚的 batch，要求该语义时在执行前拒绝；支持的部分成功模式逐项返回授权与执行结果。

发布接口调用者只能访问接口契约允许的字段、条件和操作。服务端不能把调用者传入的任意模型名、字段名、路径或通用 RPC 当成可信指令。发布版本若扩大字段或写入范围，必须重新检查发布者权限，并让维护者看到权限范围变化。

关系 bind / unbind / rebind 检查关系操作及涉及资源的授权；级联删除和间接写入也纳入检查。Operation Interface 的调用权限仅授予执行已发布契约的能力，不自动授予调用者任意模型写权限。

批量请求对每一项授权：事务模式任一项无权限则整批拒绝或回滚；允许部分成功的模式返回逐项结果。不得先执行一部分，再发现权限错误，却仍宣称整批事务成功。

### 5.2 生命周期的建议默认值

| 项目                   | V1 建议默认值                                              |
| ---------------------- | ---------------------------------------------------------- |
| 一次性配对授权         | 60 秒、仅可兑换一次，失败次数受限                          |
| Designer 普通会话      | 空闲 30 分钟、绝对有效期 12 小时；受信本机启动器可重新配对 |
| 管理敏感操作的新鲜授权 | 最近 5 分钟内通过可信本机通道或管理员再验证                |
| 新建 API Token         | 默认 30 天，默认无权限；用户选择数据库和接口后创建         |
| 普通轮换宽限期         | 默认 10 分钟，可选择立即作废旧凭证                         |
| 紧急撤销               | 无宽限期；新请求立即拒绝，相关 WS 会话关闭                 |

有效期、上限与宽限期可配置，但创建页不得默认生成永不过期的全库管理员 Token。自动化客户端使用专用服务凭证，后续可通过受保护密钥代理接入自动轮换。

撤销后的会话、权限缓存和 WS 都必须同步失效。已经进入提交阶段的事务按事务规则完成或回滚，不能为立即断开而制造半写入；排队和后续操作拒绝执行。耗时只读任务在安全取消点停止。

Cookie 使用 HttpOnly、SameSite，并在 HTTPS 场景开启 Secure。本机开发 HTTP 仅允许 loopback 的受控例外，不把该例外推广到局域网。生产推荐同源部署 Designer 与 API；开发 Origin 单独列入白名单。状态变更请求增加 CSRF 验证，WS 检查 Origin 和有效会话。

长期 API Token 不再进入 localStorage、sessionStorage、构建时环境变量或 URL。程序调用使用 `Authorization: Bearer ...`，不使用 Query 参数传 Token。多种认证头冲突时拒绝请求，避免不同入口选取不同身份。

### 5.3 外部应用自己的权限如何接入

目标是让外部应用继续管理它自己的账号、组织和业务角色，由 ModelDB 管理最终的数据访问边界。不要求把每个业务用户和角色复制到 ModelDB，也不能直接信任调用方提交的 `userId`、`role=admin` 或租户参数。

建议分两层建设：V1 支持受信应用后端持有限权服务凭证；标准令牌交换和外部身份联合列为后续扩展。两种模式的信任强度和审计含义必须分别展示。

| 接入方式               | 流程                                                                                                      | 本阶段范围                                                            |
| ---------------------- | --------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 应用后端代理           | 用户登录应用 → 应用后端检查业务权限 → 后端用专用服务凭证调用获授权接口 → 返回结果                         | 纳入 V1 的接入规范，复用 API Token 和发布接口权限，不新增外部身份协议 |
| 代表用户的短期令牌交换 | 应用后端向 ModelDB 提交受信用户访问令牌和应用身份 → ModelDB 校验并映射权限 → 颁发短期、指定资源的访问令牌 | 后续扩展，采用适用的 OAuth 2.0 Token Exchange 标准，不自创令牌协议    |
| 无用户参与的系统任务   | 应用服务通过专用服务凭证或未来的标准客户端认证访问                                                        | V1 支持独立 API Token；标准 OAuth 客户端认证可后续接入                |

V1 推荐示例：应用后端确认某员工可以查看行政区划，再使用仅授权 `AdministrativeDivision_Query` 的服务凭证调用 ModelDB。服务凭证放在后端的 Secret 存储，不发给前端，不使用实例管理员 Token。应用后端有责任验证允许的条件和参数，不能让前端请求任意接口或透传任意查询。

V1 下，ModelDB 已验证的身份是“某应用服务”。应用传入的最终用户标识只能记录为“该应用声明的用户”，同时记录声明应用与关联请求 ID，不能伪装成 ModelDB 已独立验证的用户。普通客户端任意提供的身份头不作为授权依据；如启用调用上下文，仅对指定受信应用、受限字段和长度生效。

这意味着 V1 信任应用后端正确执行自己的业务权限。它适合受控的应用集成，不等于 ModelDB 已实现用户级、行级或多租户隔离。如果需要由 ModelDB 独立保证“当前用户只能访问自己的租户数据”，应等可信上下文绑定与行级策略完善，或采用已隔离的库和专用接口；不能查询全量后只在前端隐藏数据。

未来的令牌交换至少包含以下约束：

- 管理员预先登记可信应用、身份发行方、受众、密钥来源和允许映射的权限，不按请求里的任意 URL 动态信任发行方或下载密钥。
- 应用后端先证明自己的身份，再提交面向约定资源的用户访问令牌。OIDC 登录用的 ID Token 不默认当作数据访问令牌，也不默认接受任意第三方 JWT。
- 验证签名算法、签名密钥、发行方、受众、有效期和必要的重放约束；使用受限缓存的 JWKS 或受信令牌检查端点，发行方故障时按约定拒绝新授权，不能放宽权限继续服务。
- 用户身份以发行方和主体 ID 共同标识；组织或租户声明必须来自可信映射，不能由普通查询参数覆盖。
- 最终权限为“应用获授权范围 ∩ 用户映射权限 ∩ 请求范围 ∩ 发布接口契约 ∩ 当前实例策略”，外部角色不能直接换取实例管理员或本机恢复权限。
- 交换结果默认最多有效 5 分钟，且不超过源访问令牌剩余有效期，不发长期刷新令牌；保存可撤销的授权记录。自身撤销立即生效，外部身份撤销是否即时取决于发行方的检查或事件能力，不能承诺离线 JWT 会自动即时失效。
- 审计同时记录实际调用应用、已验证用户、租户、凭证和请求 ID。交换令牌不得超出批准的数据库、接口和操作，也不作为数据库解密密钥。

若未来开放用户/租户数据范围，限制必须在查询执行前形成不可覆盖的条件，并覆盖计数、聚合、分页、关联遍历、写入、导出和缓存键。缺少可信身份或租户时拒绝执行，不能跳过条件后查询全部。这部分与完整行级权限一同设计，V1 不宣称已提供。

V1 在主体、权限和审计契约中预留 `applicationId`、身份来源、可选的用户主体及声明可信度；未实现的外部令牌认证方式明确拒绝，不保留可以绕过认证的占位入口。未来信任配置属于目标实例的安全配置，不随资产交易包自动启用。

## 6. 传输、限流、日志与本地存储

### 6.1 远程访问

新实例默认本机模式。明确开启远程模式时，支持两种部署：Server 直接提供 HTTPS / WSS；或由受信反向代理终止 TLS，Server 仅开放给代理的本机或受控网络链路。

`publicBaseUrl` 仅表示调用地址，不授予权限、不签发证书。自动 Network 地址可以继续显示，但 IP、域名、证书 SAN 和客户端信任必须匹配。自签名证书的远程首次信任需要指纹确认或预先安装受信根，不能把“忽略证书验证”作为默认方案。

生产模式发现非 loopback 明文开放且没有有效代理隔离配置时，启动检查应拒绝不安全配置并给出修改方法。不得仅因设置了 `publicBaseUrl` 就认定链路已加密，也不得盲目信任来自任意来源的 `X-Forwarded-*`。

新 wire 协议进行版本协商，使用标准序列化与 TLS。旧 XOR 编码不能作为加密层继续宣传；SDK 与 Server 不匹配时明确返回版本错误，不静默降级到旧认证协议。

### 6.2 限流与执行预算

S5.3 在现有发布接口限流之外，增加按可信来源 IP 和入口面划分的请求窗口、认证后主体窗口，以及认证失败观察/可选临时封禁。默认窗口 60 秒，每来源数据面 1000 次、管理面 240 次，每主体每入口面 1000 次；认证失败阈值 20 次，自动封禁默认关闭，启用后默认封禁 600 秒。配置由安全中心和 OS 本机 CLI 共用的防护控制入口维护。

请求次数限流已经实现；连接数、独立配对/恢复配额、查询执行时间和导入导出任务预算仍是后续集成目标，不能从 S5.3 的窗口限制推断为全部已具备。V1 建议基线为普通请求体 8 MiB、普通批量最多 100 项，大文件使用独立流式上传和大小/任务配额；各入口现有限制以对应代码与验收记录为准。

认证失败按来源与入口面计数，不永久锁定用户。超限/临时封禁返回 HTTP 429 和 `Retry-After`；封禁返回剩余秒数，请求窗口返回保守的完整窗口秒数。单实例内存最多保留 10000 个窗口键，满载拒绝新键，重启会丢失短期窗口；临时封禁持久保存原到期时间，重启不续期。多节点共享配额属于后续扩展。

### 6.3 审计和可观测性

V1 提供独立的“数据安全日志”，在安全中心中检索和统计，落盘到 `<instance-home>/audit/`，不依赖普通开发日志或业务库可用性。安全日志分为网络访问事件、安全管理审计和数据访问审计；成功调用也纳入追踪，不能只记录失败。

| 事件类别         | 必须记录的场景                                                                              | 可展示的统计                                        |
| ---------------- | ------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| 未认证与异常连接 | 访问受保护入口未带凭证、凭证无效/过期/撤销、WS 握手失败、Origin 拒绝、可识别的非法协议请求  | 来源 IP、原因、次数、首次/最后出现时间、涉及入口    |
| 网络策略         | 允许/拒绝名单命中、限流、临时封禁及解除、远程明文入口拒绝                                   | 命中规则、处置、窗口次数、封禁到期时间              |
| 安全管理         | 初始化、配对、凭证维护、会话撤销、权限修改、名单修改、TLS/代理/审计策略变更、密钥及恢复操作 | 操作者、目标、脱敏变更摘要、结果、关联任务          |
| 数据访问         | 发布接口及模型查询成功/失败、全部写操作、关系操作、批量任务、导入导出、备份恢复和资产交付   | 数据库、接口/模型、操作、返回或影响数量、耗时和结果 |

“裸连”在页面中拆成明确原因：未携带认证、认证失败、非 TLS 请求和协议异常不是同一件事。未认证请求只有实际触及受保护入口时才产生缺少认证事件；正常打开登录页、静态资源或明确公开的健康检查，不默认标记为攻击。日志描述观察到的事实，不直接断言某 IP 的使用者具有恶意。

如果“裸连”指不经过 SDK、直接使用 Postman 或 HTTP 客户端调用，这仍是支持的正常接入方式：认证有效、来源合规且具备权限即可调用并留痕。安全判定不依赖 User-Agent 或是否声称使用官方 SDK，它们可以被伪造。

每条事件至少有事件 ID、格式版本、UTC 毫秒时间、请求/连接/任务关联 ID、事件类型、结果与原因码、网络对端 IP、可信解析后的客户端 IP 及来源依据、协议与受限路由标识、已验证主体/凭证 ID、资源、策略版本、命中规则、耗时和适用的数量统计。本机管理通道记录本机身份来源，不伪造 IP。认证失败时尚未验证的 Token ID 不冒充已验证主体。

内部时间保存为明确的 UTC 时间，UI 按当前时区和语言展示年月日时分秒，同时允许查看 UTC 与时区；导出保留原始 UTC 字段，避免跨机器溯源时失去时间基准。HTTP 请求次数、WS 握手次数、网络连接次数及消息次数分别计数，页面不把它们混成同一个“访问次数”。

IP 取值先保留实际 socket 对端。仅当该对端命中受信代理配置时，才从靠近 Server 的一端逐跳裁剪已知可信代理，以首个不可信来源作为边界，不直接采用最左侧地址；不信任任意 `X-Forwarded-For`。UI 区分网络对端、客户端地址和未验证声明。共享出口或 NAT 下，一个 IP 不能等同于一个用户。

可见性也有边界：如果请求已被防火墙、CDN 或反向代理丢弃，ModelDB 本身看不到该事件；由上游提供相应访问/安全日志。TLS 在 Server 终止时可记录可获取的握手失败信息，但拿不到尚未发生的 HTTP 路由或用户身份。V1 明确展示来源和覆盖范围，后续再考虑上游日志关联与外部 SIEM 接入。

不记录 Token、Cookie、私钥、恢复码、完整查询参数值或业务结果。对开发模式全量查询日志同步整改。普通错误响应只返回稳定错误码和请求 ID；物理路径、栈和底层系统错误进入受限诊断日志，不再直接出现在用户界面。

路由记录使用模板和允许的结构化标识，不原样记录可能带秘密的 URL、任意请求头或超长输入。记录数量、结果规模和导出字节数，不复制业务行。调用方提供的用户 ID、来源或追踪 ID 均标明可信度并限制长度，防止日志注入。

对高频未认证事件做有界窗口聚合：保留来源、原因、首次/最后时间、观察次数和有限样本，并展示保存明细数与被抑制明细数；次数按观察计数统计，不能用落盘行数代替。设置内存键数量、队列和磁盘容量上限，防止恶意请求把日志系统本身打满。已认证查询逐请求记录最小操作摘要，再按凭证与资源生成统计视图；关键管理操作和数据写入逐项记录，不以采样代替。批量写入保留任务级记录和逐项结果，避免只写一条笼统的成功事件。

普通诊断日志与安全审计分别轮转。建议安全事件保留 90 天，查询汇总保留 30 天，具体时长与容量可配置；即将达到容量上限时提前告警。未到期关键审计不能静默覆盖；审计不能可靠持久化时，拒绝新的关键安全管理和数据变更操作，并暴露健康告警。变更开始前记录操作意图，完成后记录结果；跨存储中断通过持久任务日志对账，不伪造成功结果。高频拒绝事件可以受控汇总，不让单次攻击无限阻塞合法只读流量。

读取日志、导出日志、修改保留策略分别授权。UI 不提供无审计的单条修改/删除功能；到期清理、保留策略修改及日志导出也留痕。导出只含脱敏事件，默认不随资产包或普通数据备份交付给买家。IP 等溯源数据受安全日志权限和保留期限约束。

V1 本地审计提供追踪与受限访问，不声称能够抵抗拥有系统管理员权限的攻击者删除或回滚本机文件；需要此能力时接外部审计存储或不可变存储。单纯增加本地哈希链不能独立证明没有删掉最后一段日志。

指标至少包括认证失败、拒绝授权、限流命中、活跃会话、接口延迟、导入导出任务、备份成功率和恢复演练状态。指标标签不用 Token ID、原始参数等高基数或敏感信息。

### 6.4 目录、密钥和缓存

实例 Home 是唯一的默认安全目录根，不跟随当前 shell 工作目录变化。逻辑布局如下，文件格式在实现阶段冻结：

```text
<instance-home>/
  modeldb.config.json      非秘密配置与安全存储引用
  security/                实例身份、凭证注册表、策略、受保护密钥封装
  logs/                    脱敏诊断日志
  audit/                   安全事件
  cache/                   可重建缓存，不能作为密钥或恢复材料的唯一存储
```

业务 Vault 可以位于单独配置的工作区；缓存和日志不会因从该工作区启动而自动回落到 Vault 目录。备份文件继续写入仓库约定的 `<workspace>/modeldb/backups/`，外部迁移通过管理面的下载/导入能力完成；本次不顺带修改现有备份根目录规则。启动状态展示各类实际路径，权限不足时报错，不能悄悄改写到另一个目录。

安全注册表独立于业务 Vault 和 Designer 的 `sys_*` 模型，避免“先解密业务库才能认证、先认证才能取密钥”的循环。注册表采用具备事务与崩溃恢复的存储；权限和撤销状态不可因普通业务备份恢复而回滚。

这里的“安全注册表”是引擎维护的身份与凭证台账，不是把资产登记到 Windows 注册表后才能解锁。操作系统绑定只用于保护本机运行密钥；资产包依靠独立接收方或恢复封装实现跨机器交付。仅把当前明文 Token 从 JSON 移到环境变量，也不等于完成安全改造。

Windows 默认使用账号范围的 DPAPI 配合 ACL；其他平台由 SecretProvider 适配系统钥匙串、Secret Service、容器 Secret 或外部密钥服务。容器缺少系统钥匙串时必须显式挂载受保护秘密，不回退到明文配置或环境中固定默认密钥。无人值守 Linux 不能默认依赖需要图形登录才能解锁的钥匙串。

Core 只接收按库解析的密钥提供器，不再读取网络认证 Token。明文数据缓存仅在必要范围存活，退出、撤销敏感会话及密钥维护时按资源失效；落盘缓存含业务数据时同样加密或禁止落盘。任何缓存都不能绕过权限检查，也不能作为导入完整性验证的最终依据。

导入预检可以复用带版本的模型缓存、索引和批量存在性查询来优化性能；真正提交前仍检查数据版本、唯一 ID、关系两端、类型和权限，防止预检之后的数据变化产生错误。继续遵守现有 AuthoringBridge 缓存规则，不用 Vault mtime 作为无条件失效依据；恢复或替换文件时显式关闭并驱逐对应引擎实例。

### 6.5 黑白名单与网络访问策略

V1 纳入手动允许/拒绝名单、来源限流，以及可选的有时限自动封禁。不实施复杂 WAF、地理 IP 风控或机器学习判定。名单是网络边界，仍须继续认证、授权和执行预算检查；白名单不等于免密、管理员或无限调用。

| 规则对象       | V1 能力                              | 说明                                                              |
| -------------- | ------------------------------------ | ----------------------------------------------------------------- |
| 来源 IP / 网段 | IPv4、IPv6、CIDR 的允许与拒绝规则    | 规范化 IPv4-mapped IPv6；不使用易被 DNS 变化影响的主机名规则      |
| 入口           | 分开设置管理面和数据调用面的来源策略 | 公开数据接口不意味着开放安全中心和管理 RPC                        |
| 单个应用或凭证 | 在全局规则之上增加来源范围限制       | 只能收紧全局范围，不能绕过实例拒绝规则                            |
| Origin         | 浏览器页面的允许来源                 | 与 IP 白名单分别管理；Origin 可被非浏览器客户端伪造，不能作为身份 |
| 已认证主体     | 撤销凭证、停用设备/应用、撤销会话    | 使用身份生命周期机制，避免再维护一份互相冲突的身份黑名单          |

判定顺序为“可信来源解析 → 全局/入口拒绝规则及临时封禁 → 已启用的来源允许规则 → 认证 → 主体级来源限制与权限 → 限流/预算 → 执行”。认证前后都可按各自维度限流；即使提前拒绝，也记录原因、来源和命中规则。WS 连接建立后不只检查一次，规则更新须影响后续消息。

相同范围内拒绝优先于允许，适用的多层限制取交集。允许名单关闭表示该层不限制来源；允许名单开启但为空表示全部拒绝，页面明确提示，不能偷偷解释为全部允许。未来外部应用信任配置也不能覆盖网络拒绝。

默认本机监听，未启用远程访问时不额外强迫用户填写 IP。开启远程访问时，管理面默认保持 loopback 或经批准的管理网段；数据面由管理员选择来源网段，动态公网客户端可明确选择任意来源，但仍必须通过 TLS、限权凭证和限流。无论来源是否为 loopback，都不因此跳过认证。

每条规则保存 ID、类型、入口范围、来源、原因、创建者、创建/到期时间和状态。长期手工规则持久保存；临时规则过期自动解除并记录事件。V1 自动封禁默认仅观察和告警，启用后采用可配置窗口、阈值和短期封禁，初始建议窗口 60 秒、20 次认证失败、封禁 10 分钟；共享出口场景需先评估，不能默认永久拉黑。

自动封禁结合来源、入口以及认证后的主体限制，避免用猜测的用户标识触发他人封禁。允许来源仍接受限流；可单独配置跳过自动 IP 封禁的管理来源，但不能免除手工拒绝、认证或权限检查。V1 不把公网 IP 当作稳定设备身份。

网络策略变更先做严格语法检查和当前管理请求/已建 WS 的命中预览。预览有效期 120 秒，绑定完整配置、当前 revision 和操作者；应用时检查 revision，拒绝过期、跨操作者、配置变更和并发覆盖。应用立即执行新策略，进入 120 秒待确认期；必须从新策略允许的管理路径或 OS 本机通道确认，否则自动回滚。重启保留原截止时间，发现时钟早于持久策略时间时回滚待确认变更。已确认配置支持按 revision 回滚上一份配置；回滚不撤销独立的封禁状态。

应用、回滚和临时封禁更新后立即重检已建 WS，被拒绝连接以 1008 关闭，后续请求仍经过安全边界；已进入事务提交的写操作按事务契约处理。规则、策略版本和封禁保存在独立 registry，启动及周期清理到期记录并审计，时钟在进程内保持单调。持久化或审计失败不发布新策略，受影响边界 fail-closed。本机受 ACL 保护、验证 OS 身份的 Named Pipe 保留修复和解封能力，普通 loopback HTTP 不享有豁免。

实例级网络名单不随业务备份恢复而回滚，也不随资产交易包自动安装。接收者决定自己的网络边界；包中即使包含部署建议，也仅展示待确认信息，不作为可执行安全配置。

## 7. 重置与维护必须分成不同操作

| 操作               | 做什么                                         | 对现有数据的影响                                                     |
| ------------------ | ---------------------------------------------- | -------------------------------------------------------------------- |
| 轮换某个 API Token | 创建新凭证，按宽限期撤销旧凭证                 | 不修改数据库密钥或数据                                               |
| 重置全部访问凭证   | 撤销现有 API Token、设备与会话，重新配对管理员 | 保留业务 Vault 和密钥；外部客户端需要重新授权                        |
| 轮换实例主密钥     | 用新 IMK 重新封装 DEK，保留历史 IMK            | 不重写业务 Vault；独立恢复封装在 S6 实现                             |
| 轮换某个数据库密钥 | 生成新 DEK，分阶段重新加密该库                 | 需要写入门禁、进度、可恢复日志和空间预算                             |
| 通过恢复材料接管   | 验证恢复材料，在新环境重新封装数据密钥         | 保留数据，默认撤销旧会话并创建新的实例访问身份                       |
| 恢复出厂设置       | 删除指定实例的数据和安全状态                   | 破坏性操作；明确目标、尽量先创建安全备份、二次确认，CLI 需要 `--yes` |

本机 CLI 不因连接来自 `127.0.0.1` 就允许重置；它通过受保护本机通道验证调用者的 OS 身份。远程安全中心的敏感维护需要新鲜的管理员授权。独立恢复材料允许数据恢复，但不自动恢复源实例的所有管理员身份和信任关系。

如果怀疑只有 API Token 泄露，撤销并审计即可。如果怀疑主密钥或数据库明文已泄露，则应轮换受影响数据密钥并排查备份和交付范围；仅修改 Token 无法追回泄露的数据。

主密钥轮换、DEK 轮换、恢复替换采用任务化状态机：预检、准备、写入、验证、提交、清理。中断后可以确定地恢复，不出现密钥已换而 Vault 未换的状态。需要保留旧密钥时明确原因与保留期限，销毁前检查仍依赖它的备份。

S5.3 已实现 IMK 原子提升、历史 IMK 保留、逐 DEK 重封装和持久轮换状态；提升或重封装中断后，启动/重试续接同一任务，Vault 字节和 key reference 不变。历史 IMK 当前不自动销毁，最多保留 1000 项，达到上限拒绝新轮换；历史依赖核查、销毁策略、DEK 重新加密和独立恢复仍由 S6 交付。浏览器轮换要求安全管理员会话、Origin/CSRF 和距配对凭证创建不超过 5 分钟的新鲜授权，刷新会话不延长此期限；OS CLI 需要 `--yes`。

出厂清除仅提供离线 CLI：要求现存 registry、独占实例与密钥维护锁、精确 instanceId、解析后的 workspace 目标和 `--yes`。拒绝根目录、重叠目录、junction/符号链接及超限目标（合计最多 10000 文件、128 MiB），先在目标外创建 AES-GCM 加密、Windows DPAPI 保护密钥的备份，并实际解密验证。删除前持久写入 tombstone、复核每个文件哈希，删除完成后写回执；配置、日志和目标之外的文件保留。中断后 tombstone 阻止普通启动，当前未提供清除续跑/归档恢复工具，须保留外部归档和现场，不能直接移除标记后重启。该同机同账号归档不构成异机灾备。

## 8. 备份、移库与资产图谱交易

本节描述 SEC-M6 的交付目标与实施边界。S6.1 已实现本地独立恢复材料、历史密钥快照/依赖检查和离线 DEK 轮换；异机 Windows 实机演练待验证，不能宣称 S6.1 或 SEC-M6 完成。S6.2 已实现单库加密备份和完整受信迁移，证据见 SEC-M6 / D03。两端合成恢复演练见 D02，同机同账号运行不能产生异机成功证据。S6.3 / D04 交付模型子集；D05 增加明确 v2 Designer 接口/固定版本依赖、显示元数据引用映射和离线双库持久日志/分阶段发布。仅 CLI，导入接口禁用，普通启动阻断未完成任务；完整 UI 与更广泛资产兼容验收仍待，S6.3 保持进行中。当前验证和限制以 D05 为准。

S6.1 的恢复文件采用固定标准 JWE `RSA-OAEP-256` / `A256GCM`，恢复私钥由 scrypt 及 AES-GCM 保护，具体格式和限制见 Vault 契约。文件包含生成时所有当前/历史 IMK 和 DEK，不包含源 DPAPI blob、访问凭证、会话或网络策略。当前采用显式快照导出模式：新增库、轮换 DEK 后重新生成恢复材料；`recovery-check` 只检查指定原始 Vault/备份副本的公开密钥依赖，不能替代完整文件真实性/业务恢复验证。恢复公钥登记后的自动封装更新仍是后续备份链路目标，当前不会自动发生。

DEK 轮换为离线操作，要求实例身份、精确配置库路径及 `--yes`，持有实例和密钥维护锁；任务绑定旧文件摘要和新旧 key reference，通过双密钥认证恢复 journal。旧 DEK 不自动销毁，保证历史备份仍可使用。未完成任务阻止普通 registry 启动，只允许恢复 CLI 接续。独立恢复仅发布到全新安全目录，暂存完成后重新解封每个 DEK 并原子发布，目标生成新 IMK 并使用自己的 Windows DPAPI 保护；保留 Vault key domain，重新建立空访问台账，访问必须重新授权。恢复锁阻止普通启动，发布前后硬退出可原命令重试；已有结果只对同包、receipt/身份/全部 DEK 匹配且未初始化访问台账的目标幂等确认。源和已有目标配置/策略不被导入或覆盖。

### 8.1 三种交付物分别处理

2026-10-22 按用户继续下一步骤的指令开发 S6.2；保留 S6.1 异机实测待验证。单库一致性快照采用 `modeldb.backup.v2` 完整包加密：独立随机 PEK，标准 JWE General JSON 多接收方封装（本机/恢复用历史 DEK 的 `A256KW`，显式完整迁移接收方的 `RSA-OAEP-256`），正文 `A256GCM`。正文只包含该库的 Vault 和所需单个 DEK；manifest 和统计位于公开且经过认证的 protected header，不递归打包目录，不包含实例凭证或策略。恢复先完整验证，再以目标库自己的 DEK 重加密、映射内部 atlas/checksum 并原子提交。迁移导入先存为目标本地备份，再显式恢复为新库；旧 JSON v1 在安全路径明确拒绝，保留原件。格式见 Vault 契约第 8 节，操作见[使用手册](security-v1/user-guide.md)。

| 类型         | 主要目的                                 | 凭证与密钥处理                                                         |
| ------------ | ---------------------------------------- | ---------------------------------------------------------------------- |
| 日常备份     | 在误操作、文件损坏或机器故障后恢复       | 全包加密，包含恢复所需的密钥封装；不包含可直接使用的管理员 Token       |
| 完整受信迁移 | 把一个完整数据库迁到自己控制的另一实例   | 通过迁移包让目标实例重新封装数据库密钥；明确源实例和目标实例的身份变化 |
| 资产交付包   | 出售或分享指定图谱、模型、接口和可选数据 | 为选定内容生成独立包密钥，绝不把源库 DEK 交给买家                      |

迁移只有在完整、受信和明确选择的场景下才考虑封装现有 DEK。资产交易和部分数据导出必须使用新 PEK，否则买家可能利用源 DEK 解锁卖家的其他备份。

Excel 数据导入导出继续服务人工编辑和模板填充；它不是加密资产包、密钥备份或完整系统迁移的替代品。导出 XLSX / CSV 等可读数据必须有独立权限与脱敏选择，并明确文件中包含可读业务数据；其中不导出系统秘密字段或访问凭证。聚合、计算结果可导出为只读报表，继续不支持反算导入。

### 8.2 资产包的内容

允许选择模型结构模板、结构加数据、接口及依赖，或完整资产图谱。清单至少包含格式版本、资产永久 ID、资产版本、来源实例标识、发布者标识、依赖、模型与字段映射、接口契约版本、数据与关系数量、内容摘要、签名和接收方密钥标识。

数据内容保留唯一 ID 与关系路径，便于验证和冲突处理；同时区分“资产永久 ID”和“本地数据库实例 ID”。导入生成新的本地实例 ID，不把买家的实例误认为卖家的原实例。

Query Designer 的发布台账、Binding Surface 等元数据可能保存在单独的 Designer 系统库。打包器必须按资产归属和依赖选择性提取，并映射内部引用；不能为方便而把整个 Designer 系统库、其他资产的接口或用户会话一起导出。

UI 展示、i18n 元信息及接口选中字段随资产依赖打包。原始数据的层级与关系信息必须完整；不把运行结果的扁平表格当成全部关系定义。

### 8.3 导入和恢复流程

1. 检查文件体积、条目数量和格式版本，解析受限清单。
2. 校验接收方、签名、摘要及加密完整性。签名只证明对应私钥持有者签过内容；发布者是否可信，还需要用户信任、已验证指纹或平台信任链。
3. 在隔离暂存区解密和预检，展示模型、字段、数据、关系、接口、冲突以及所需权限。
4. 默认导入为新库；覆盖或合并必须显式选择，并明确 ID 冲突策略。不能静默覆盖同名资产。
5. 写入目标实例保护的新 Vault，验证关系双向完整性与接口依赖，重建索引和非权威缓存。
6. 涉及业务 Vault 与 Designer 系统库的跨存储更新使用持久任务日志和分阶段发布；全部验证完成前不对普通用户开放半成品。没有跨库存储事务时，不宣称已经具备原子跨库事务。
7. 返回逐阶段反馈、统计、错误路径和可重试信息，清理暂存明文；保留脱敏审计。

导入器拒绝路径穿越、绝对路径、符号链接、Windows ADS、重复路径、超限解压、超限 KDF、未知危险扩展和不允许的版本降级。资产包中的内容不作为任意脚本、插件或系统命令执行。

备份读取采用一致性快照或受控写入屏障，关联元数据也有一致版本。恢复前校验备份、恢复权限和密钥可用性；替换业务库时关闭相关引擎与会话，显式驱逐缓存后重新打开。恢复业务备份不能重新激活已撤销 Token 或旧设备会话。

### 8.4 自动备份与交易边界

安全初始化不会暗中开启周期备份，沿用当前“自动备份默认关闭”的规则。用户启用后，备份使用独立包密钥及本机历史 DEK 的实例封装，与同库写操作共用锁并先刷盘。S6.2 的显式离线迁移可以加入接收方公钥封装；当前未提供恢复公钥登记和自动备份接收方配置，不把它描述为已经实现。独立恢复依赖另外维护且覆盖当前/历史密钥的恢复快照。

本机备份和独立灾备分别显示状态。备份文件不能只依赖某个随时可能轮换的网络 Token。完成备份不等于完成可恢复验证，应提供定期验证与隔离恢复演练。

V1 建设资产交付的技术基础，不包含交易平台、支付、版权裁决或防复制 DRM。买家一旦获得可解密内容，就可能复制数据，密码学不能阻止这一点。需要持续可撤销访问的商品应采用托管 API 订阅；撤销订阅也不能收回买家先前合法下载的数据。

## 9. 安全中心、CLI 和配置

### 9.1 安全中心页面

安全中心采用完整工作页面，保持进入前所选编辑器，返回后恢复原工作上下文。敏感设置不塞入狭窄侧栏；所有长期 UI 文案提供中文、英文和日文。

| 页面区域   | 展示和操作                                                                 |
| ---------- | -------------------------------------------------------------------------- |
| 概览       | 实例 ID、安全模式、实际数据/日志/缓存路径、TLS、本机保护和独立恢复准备状态 |
| 访问凭证   | 名称、范围、到期、状态、最近使用；创建、轮换、撤销；原文仅创建时交付一次   |
| 设备与会话 | 设备、来源、权限、到期；撤销单个设备或全部会话                             |
| 权限       | 角色预设与数据库、模型、接口、数据导出等具体授权                           |
| 密钥与恢复 | 主密钥/DEK 状态与版本、恢复包登记、恢复演练、受控轮换任务                  |
| 网络       | 监听地址、对外调用地址、证书、允许的 Origin、可信代理                      |
| 审计       | 可过滤事件、失败原因与请求 ID；受权限约束的脱敏导出                        |

补充入口：网络区域提供管理面/数据面的黑白名单、临时封禁列表、规则命中预览及受控解除；审计区域提供“来源 IP / 时间 / 原因 / 应用 / 凭证 / 数据库 / 接口”筛选，展示未认证访问次数、首次/最后时间和成功/失败数据操作。未来外部身份接入单独放在“受信应用”区域，V1 仅显示应用服务身份和权限，不显示尚未实现的令牌交换开关。

权限或密钥没有变化时，不通过自动刷新让页面和工具栏反复闪烁。异步任务显示稳定布局、进度和最终结果；敏感明文不出现在通知、剪贴板历史提示或错误堆栈中。

### 9.2 已实现的 CLI 与后续恢复入口

以下为 registry 模式已实现的命令，均显式指定实例配置；首次启动自动初始化，无需额外的 `security init`。在线维护通过验证 OS 身份的本机通道，出厂清除仅离线执行。示例只说明参数，不授权对真实实例执行。

```powershell
# 状态、独立安全中心和业务工作区启动器
modeldb-server security status -c <config>
modeldb-server security security-open -c <config> --url http://127.0.0.1:5175/
modeldb-server security browser-open -c <config> --url http://127.0.0.1:5175/ --databases graph

# 主体及凭证；grants.json 使用共享授权契约，不通过命令行传秘密
modeldb-server security principal-create -c <config> --name reporting-client
modeldb-server security token-create -c <config> --principal <principal-id> --name reporting-client --grants-file <grants.json> --days 30 --output <protected-new-file>
modeldb-server security credentials -c <config> --offset 0 --limit 25
modeldb-server security token-rotate -c <config> --id <credential-id> --grace-minutes 10 --output <protected-new-file>
modeldb-server security token-revoke -c <config> --id <credential-id>
modeldb-server security reset-access -c <config> --yes

# 有界审计查询与新建 JSONL 导出
modeldb-server security audit -c <config> --limit 50 --category network
modeldb-server security audit-export -c <config> --output <new-file.jsonl> --category network

# rules.json 是 network-status 结果中 config 字段的完整配置
modeldb-server security network-status -c <config>
modeldb-server security network-preview -c <config> --rules-file <rules.json>
modeldb-server security network-apply -c <config> --rules-file <rules.json> --revision <revision> --preview <preview-id>
modeldb-server security network-confirm -c <config> --id <pending-id>
modeldb-server security network-rollback -c <config> --revision <current-revision>
modeldb-server security network-unban -c <config> --id <ban-id>

# IMK 维护；主密钥轮换保留历史 IMK，不重写 Vault
modeldb-server security maintenance-status -c <config>
modeldb-server security master-rotate -c <config> --yes

# 停止目标实例后，使用维护状态给出的精确 instanceId 和 workspace
modeldb-server security factory-reset -c <config> --instance <instance-id> --target <exact-workspace> --yes
```

凭证输出目录需预先具备正确 ACL，凭证文件采用新建模式；审计导出拒绝 registry 目录及 junction 别名。默认不把秘密打印到日志或终端。命令细节见 `modeldb-server security help`。独立恢复材料导出/验证、DEK 轮换和异机恢复仍待 SEC-M6，不提供可误认为已经可用的命令示例；恢复包与解锁材料应分开保存。

### 9.3 计划中的配置形态

以下 JSONC 用于解释新结构，不是当前版本可直接加载的配置，也不要求用户安装后手写。配置生成器应自动提供默认值，现有非安全配置另行保留。

```jsonc
{
  "port": 9091,
  "host": "127.0.0.1", // 默认只允许本机网络连接
  "publicBaseUrl": "", // 仅用于展示对外调用地址，不代表 TLS 或授权
  "security": {
    "mode": "local", // 开启远程访问时需通过远程安全预检
    "secretProvider": "auto", // 按运行环境选择系统保护；不可用时不回落到明文
    "session": {
      "idleTimeoutMinutes": 30,
      "absoluteLifetimeHours": 12,
    },
    "apiToken": {
      "defaultExpiresInDays": 30,
      "rotationGraceMinutes": 10,
    },
    "browser": {
      "allowedOrigins": [], // 生产同源由部署信息确定，额外 Origin 必须明确登记
    },
    "remote": {
      "enabled": false,
      "tls": { "mode": "disabled" }, // 仅限本机模式；远程需 direct 或受信代理模式
      "trustedProxies": [],
    },
  },
  "autoBackup": {
    "enabled": false, // 安全初始化不替用户决定周期备份与外部保存位置
    "intervalMs": 60000, // 沿用现有最小调度间隔；未启用时不会开始定时备份
  },
}
```

配置中不出现 `connectToken`、Vault 解密密码、恢复码或私钥原文。必要证书、容器 Secret 和外部密钥服务通过文件/提供器引用接入，并检查权限。

### 10.2 按依赖推进的七个阶段

| 阶段                             | 实际交付                                                                                       | 阶段验收                                                                    |
| -------------------------------- | ---------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| S1：密钥与 Vault 基础            | 冻结威胁边界、格式和密钥提供器契约；实现独立 IMK / DEK、Windows 本机保护、旧格式识别与安全写入 | Token 不再参与 Vault 解密；错误密钥、断电与写入失败不覆盖有效库；重启可读   |
| S2：实例身份与凭证生命周期       | 独立安全注册表、本机管理通道、自动初始化、API Token 生命周期、应用服务主体、审计写入基础       | 无明文配置秘密；本机 TCP 不能冒充管理员；撤销持久；关键身份操作从实现起留痕 |
| S3：全入口统一授权               | HTTP / WS / bulk / 发布接口共用权限检查；资源边界、受信应用后端接入、审计上下文                | 限权凭证无法转为任意模型查询；批量/关系无越权；声明用户不能冒充已验证身份   |
| S4：安全传输与自动 Designer 会话 | HTTPS/WSS、可信代理、Origin/CSRF、新 SDK/wire、本机启动器配对、来源策略执行                    | 本机无需复制 Token；远程不明文传秘密；伪造代理头不能绕过名单或伪造来源      |
| S5：安全中心、限流与审计         | 完整页面、设备/凭证管理、配额、数据安全日志、黑白名单/临时封禁管理、健康指标                   | UI/CLI 一致；次数可解释、事件可归因；名单生效且有可信本机修复路径           |
| S6：恢复、备份和可迁移资产       | 独立恢复材料、历史密钥管理、完整包加密与签名、资产依赖导入导出                                 | 异机恢复成功；业务恢复不复活旧凭证；买家包不能解密源库其他数据              |
| S7：发布前验证与交付             | 故障注入、回归、安装/重装/账号变化演练、性能对比、文档与配置同步                               | 满足下方发布门槛，能够重现本机使用、远程调用、重置、移库和灾备全过程        |

S1、S2 是基础，S3 依赖凭证主体，S4 接入浏览器与 SDK，S5 提供维护入口，S6 建立恢复与资产交付，S7 集成验收。每阶段保留可审查结果，不把所有安全变更堆到最后一次大切换。

审计事件契约在 S1 定义，S2 起每项安全变更接入审计写入，后续阶段补齐数据与网络事件；S5 完成检索、聚合和管理 UI，不能到 S5 才开始记录安全操作。外部令牌交换和行级/租户策略仍属于后续扩展，不增加 V1 的实施阶段。

独立恢复的格式和职责在 S1 就要确定，避免 S6 才发现早期密钥不可恢复。S6 完成前，可以对新格式做研发验证，但不把它宣称为已经具备异机灾备的正式发布版本。TLS 和授权未同时完成前，也不对远程开放新的管理入口。

Windows 是当前首要验证平台。其他平台要分别完成 SecretProvider 与无人值守启动验证后，才能列入受支持部署；不会把 Windows DPAPI 实现直接宣称为跨平台安全支持。

### 10.4 依赖、验证与环境切换规则

主依赖为 `S1 → S2 → S3 → S4 → S5 → S6 → S7`。恢复格式在 S1 定义，S6 完成使用链路；审计结构在 S1 定义，S2 开始写入；名单执行在 S4 完成，S5 完成维护体验。阶段状态使用未开始、进行中、待验证、完成、受阻，不能把文档完成视为功能完成。

每阶段交付后报告：完成任务、用户可见变化、执行过的验证、尚未完成的能力以及下一项任务。仅在对应能力确实可用时更新状态；测试失败或缺少必要的平台验证时，不提前标记完成。

验证采用三层：纯契约/权限/加密单元验证，隔离临时目录中的 Server/SDK 集成验证，以及 Windows 安装、浏览器配对和独立恢复的真实环境验证。故障用例必须证明文件和密钥的恢复状态，不能只断言抛出错误。新功能测试不直接写现有业务 Vault。

现有库切换分成盘点、保存可用快照及必要旧秘密、隔离新格式验证、明确选择重建/迁移、切换客户端与服务、最终验收。旧格式可以明确停止支持，但不做静默删除或自动覆盖。保存的旧秘密只进入受保护切换材料，不进入代码库或普通日志。

普通业务恢复不回滚安全注册表；若整实例故障必须使用专门的安全恢复流程，重新建立访问身份并默认作废旧认证状态，避免从旧实例快照复活已撤销凭证。失败回退不得把新格式库直接交给旧程序写入。

本方案不预报未经验证的工期。完成 S1 后，按确定的本机密钥适配成本、存储改造量和基准验证结果细化后续工时；在此之前以任务和验收结果控制进度。

## 11. 正式收尾的验收清单

- 全新实例无需编辑秘密配置，通过本机启动器可以自动进入 Designer；普通 HTTP 客户端无法抢占管理员。
- 重启、并发首次启动和初始化中断后，实例 ID、凭证与数据密钥一致，不出现重复实例或空库覆盖。
- Token 轮换后 Vault 内容无需重加密；新旧凭证宽限期、过期和紧急撤销符合契约。
- 已撤销凭证在 HTTP、现有 WS、批量入口和进程重启后均不可继续执行新操作。
- 发布接口调用者不能访问未选中字段、其他数据库、通用 RPC 或系统管理模型；关系与间接写入检查完整。
- 密钥缺失、认证标签错误、文件损坏、磁盘空间不足和提交中断时保留可恢复状态，不悄悄重建库。
- 主密钥轮换、DEK 轮换与访问重置分别验证；旧备份在约定历史密钥保留期内仍可恢复。
- 远程 HTTPS/WSS、证书错误、Origin/CSRF、可信代理与代理伪造分别验证；无静默不安全降级。
- 未带认证、无效/撤销凭证和 WS 失败可按可信来源 IP 检索次数、时间与原因；正常公开页面不误报为缺少认证。
- 模拟日志洪泛、磁盘满和日志队列拥塞，验证计数/样本区别、内存上限、告警和关键变更拒绝策略。
- 查询、数据变更和安全管理事件可关联主体、资源与请求 ID；外部应用声明的用户明确标记为声明身份。
- IPv4/IPv6/CIDR、拒绝优先、允许名单开启但为空、入口分离、规则过期、重启持久及已有 WS 的新规则生效均验证。
- 伪造 `X-Forwarded-For` 不能避开名单、限流或伪造已验证来源；修改名单误锁后可由可信本机通道修复。
- 资产包导入和业务备份恢复不改变目标实例的网络名单、外部应用信任或审计权限策略。
- 浏览器存储、前端产物、配置、日志、错误、指标和审计导出均不含长期凭证、私钥或恢复码。
- 新机器在没有源机器 DPAPI、没有旧 Token 的情况下，仅凭正式恢复材料可恢复备份。
- 资产交付包包含选定模型、原始数据、关系、接口、版本和 i18n；不混入其他图谱或源实例秘密。
- 资产篡改、未知签名者、ID 冲突、路径攻击、超限解压及恶意 KDF 有明确处理和反馈。
- 恢复普通业务备份不回滚安全注册表，不复活已撤销的会话与凭证。
- 模型设计、Query / Operation Interface、Binding Surface、分页、Pivot 预览、Excel 导入导出和备份已有流程回归通过。
- 测量查询、批量写入、导出与启动的开销，区分 TLS、权限和 Vault 加密成本，依据结果调优，不预先承诺零性能影响。
- 安全中心、CLI 帮助、默认配置、安装指南和故障恢复说明一致，长期 UI 文案覆盖 zh / en / ja。

## 12. 本方案的实施边界

V1 要交付默认安全初始化、独立认证与加密、最小权限调用、受信应用后端接入规范、可撤销会话、维护重置、数据安全日志、黑白名单、可验证备份、独立恢复和可迁移资产包。标准外部令牌交换、企业身份联合、完整行级/租户授权、市场交易平台、硬件密钥、KMS 多节点高可用、外部不可变审计和 DRM 为后续扩展。

研发顺序与下一项任务以里程碑台账的最新交付记录为准。实际切换旧环境前，应形成明确的库清单和新格式验证结果，再执行用户明确授权的重建或迁移操作。
