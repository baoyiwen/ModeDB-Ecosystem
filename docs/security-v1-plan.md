# ModelDB 安全改造 V1 方案

状态：待实施的研发方案。本文不表示这些能力已经实现，也不授权删除现有库、轮换当前凭证或修改正在运行的服务。

适用范围：ModelDB 引擎、Server、SDK、Model Designer、Query / Operation Interface、Binding Surface，以及备份、恢复和资产图谱交付。

## 1. 最终要达到的体验

安全改造需要同时满足三个目标：安装后本机可直接使用；需要时可以管理和重置安全机制；数据资产可以安全备份、迁移和交付。

推荐采用“自动初始化、本机可信配对、凭证与数据密钥分离、资产独立封装”的方案。

| 使用场景               | 目标体验                                                           | 安全约束                                                                      |
| ---------------------- | ------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| 首次安装、本机使用     | 自动创建安全目录和密钥，通过本机启动器打开 Designer 后自动建立会话 | 不要求手动编写 Token，不提供通用默认密码；本机 TCP 请求不能自动获得管理员权限 |
| 后续本机启动           | 自动加载受操作系统保护的密钥，恢复正常使用                         | 密钥不可用时停止打开受影响的库，不自动生成替代密钥覆盖原文件                  |
| Postman / 外部程序调用 | 在安全中心创建指定数据库、指定接口的凭证                           | 使用 HTTPS 和有范围、有有效期、可撤销的 API Token                             |
| 局域网或公网使用       | 明确开启远程访问，配置证书或反向代理，再配对远程设备               | 自动显示 Network 地址只解决地址发现，不代表完成身份验证或 TLS 信任            |
| 更换 API Token         | 在安全中心或 CLI 轮换，调用方更新凭证                              | 不重新加密数据库，不影响 Vault 解密                                           |
| 快速移库               | 导出迁移包，在目标实例验证、预览并导入                             | 接收方使用自己的实例密钥；不复制源实例管理员凭证                              |
| 资产图谱交易           | 导出指定资产范围的独立交付包，按买家密钥封装                       | 交付包不能解锁卖家的其他库、其他资产或后续备份                                |
| 本机身份失效           | 通过有权限的本机管理员或独立恢复材料恢复访问                       | 重置认证不等于找回已经丢失的数据加密密钥                                      |

“全自动”的边界需要明确：自动初始化不要求日常手工管理密钥，但异机灾难恢复必须有一份独立于本机的恢复材料。远程设备首次信任、可信证书和外部备份目的地，也无法在完全没有授权或配置的情况下安全猜测。

本方案重点防范凭证泄露后的横向访问、未授权网络调用、浏览器跨站请求、磁盘或备份文件被单独窃取、误操作和不可信导入包。TLS 保护传输，Vault 加密保护离线文件，权限控制保护在线访问，它们不能互相替代。

已经控制服务器进程、操作系统管理员账号或当前受信用户会话的攻击者，可能读取运行中的明文或调用解密能力；DPAPI 不能解决这类主机完全失陷的问题。本方案也不声称阻止合法接收者复制已经解密的数据。

## 2. 当前实现与需要修改的原因

以下判断以当前源码为准。仓库部分旧文档声称连接 Token 与 Vault 密钥已经独立，但实际代码仍有耦合，交付时必须同步修正文档。

| 当前实现                                                                                                              | 影响                                                                               | V1 改造                                                          |
| --------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| `packages/common/src/atlas-vault-secret.ts` 从 `connectToken` 派生 Vault secret；Core 与 AuthoringBridge 依赖这条链路 | 直接换 Token 可能导致原库无法解密；认证泄露也会影响数据密钥安全                    | 独立生成数据库密钥，由专门的密钥提供器交给 Core                  |
| 默认初始化把随机 Token 写入配置；CLI 还可打印 Token、通过命令行接收 Token                                             | 配置、命令历史和进程参数可能泄露长期凭证                                           | 配置只引用安全存储；凭证创建后仅交付一次，支持受保护文件输入输出 |
| HTTP / WS 主要验证同一个全局 Token                                                                                    | 调用者身份、权限范围、过期、撤销和调用归因不足                                     | 建立凭证注册表和统一权限检查                                     |
| Designer 可把长期 Token 放入 localStorage；存在 `VITE_MODE_DB_TOKEN` 回退                                             | 浏览器脚本或构建产物可能持有长期凭证                                               | 短期会话、明确配对、移除构建时生产密钥                           |
| wire codec 包含 XOR 编码以及从 Token 派生的会话材料                                                                   | 不能把这些编码视为标准的网络加密和完整性保护                                       | 远程使用 TLS；新协议移除对自制加密的安全依赖                     |
| CORS 较宽松，WS 未形成统一 Origin 信任策略                                                                            | 浏览器跨站访问边界不完整                                                           | 明确 Origin 白名单、WS Origin 验证、Cookie 场景的 CSRF 防护      |
| 已有发布接口访问规则和部分接口级限流                                                                                  | 有可复用基础，但不能代替全入口身份与权限控制                                       | 保留发布策略，并统一接入主体权限、限流和审计                     |
| 备份把文件以 Base64 放入 JSON；其中 Vault 自身已有加密                                                                | 外层包并非独立的可迁移密钥包，也不具备完整的来源签名；不能简单认定整个库是明文备份 | 增加完整包加密、密钥封装、签名、恢复依赖与验证                   |
| Vault 保存使用临时文件后复制覆盖目标                                                                                  | 复制覆盖不能直接视为断电安全的原子提交                                             | 对密钥、目录和 Vault 更新设计日志、同步与崩溃恢复                |

V1 可以破坏旧的配置、SDK 协议和 Vault 格式兼容性。主路径采用新库重建，不投入复杂的在线无感迁移。但实施时仍需识别旧格式、清楚报错、保留旧文件；获得明确删除指令前，不删除现有测试库。

## 3. 身份、凭证和密钥如何分工

### 3.1 凭证只负责“谁可以做什么”

| 类型          | 用途                                                   | 保存方式                                                |
| ------------- | ------------------------------------------------------ | ------------------------------------------------------- |
| 本机管理身份  | 安装者、获授权操作系统账号通过本机管理通道执行管理操作 | Windows SID / Unix 用户与本机通道 ACL，不靠来源 IP 判断 |
| Designer 会话 | 浏览器日常设计、查询、管理                             | 服务端可撤销的短期会话；浏览器持有 HttpOnly 会话 Cookie |
| API Token     | SDK、Postman、后台程序调用                             | 调用端保存原文；服务端只保存摘要及权限元数据            |
| 设备配对记录  | 确认远程或本机设备的后续会话申请                       | 设备标识、公钥或受保护的续期凭据，可单独撤销            |
| 恢复授权      | 本机安全状态损坏或换机后的恢复                         | 独立恢复材料，仅在恢复流程使用                          |

API Token 推荐格式为 `mdbt_v1_<credentialId>_<randomSecret>`。随机秘密至少 32 字节，使用密码学安全随机源。Token ID 用于查找记录；秘密摘要使用标准算法并做恒定时间比较，不把 Token 原文保存到业务库或日志。

注册表至少保存：ID、名称、创建主体、创建时间、到期时间、状态、授权资源、操作范围、轮换来源和最近使用时间。最近使用时间可以批量更新，但撤销和权限变更必须立即持久化。

不使用无服务端状态的长期 JWT 作为唯一认证方案，避免撤销只能等待到期。V1 优先采用可立即撤销的不透明会话和 API Token。

### 3.2 数据密钥只负责“数据如何解密”

| 密钥               | 用途                               | 轮换影响                                   |
| ------------------ | ---------------------------------- | ------------------------------------------ |
| 实例主密钥 IMK     | 在本机封装各数据库的数据密钥       | 重新封装数据库密钥，通常不重写业务数据     |
| 数据库数据密钥 DEK | 加密某一个数据库的敏感数据         | 需要重新加密该数据库，属于维护任务         |
| 恢复密钥           | 让独立备份可以在本机密钥丢失后恢复 | 更新恢复封装及恢复材料，保留必要历史版本   |
| 导出包密钥 PEK     | 加密一次备份或交付包的内容         | 每次交付独立生成，不与源数据库共用数据密钥 |
| 发布者签名密钥     | 对资产清单与内容摘要签名           | 更新签名身份与信任信息，不用于解密 Vault   |

核心关系：

```text
操作系统安全存储 → 实例主密钥 → 数据库密钥 → Vault
独立恢复材料     → 恢复封装   → 所需历史密钥 / 备份内容
接收方密钥或口令 → 包密钥     → 本次交付包
```

API Token 不参与以上数据解密链。签名密钥也不与认证或数据加密密钥共用。

数据库继续使用成熟的认证加密，例如 AES-256-GCM；随机数、认证标签、版本和密钥 ID 均进入格式规范。认证附加数据绑定数据库实例 ID、数据对象与格式版本，防止把密文搬到不属于它的对象上。密钥封装单独绑定 DEK ID 和所属数据库，避免主密钥轮换必须重写全部业务密文。

接收方公钥封装采用经过评审的标准方案和成熟实现，例如适用的 HPKE / JWE，不自行发明混合加密协议。口令导出使用带随机盐、参数版本和计算成本的成熟 KDF；优先评估现有 Node scrypt 能力。导入器限制 KDF 参数上限，避免恶意包要求无限内存。具体库选择与性能参数在第一阶段定稿。

## 4. 安装后如何自动可用

### 4.1 新实例第一次启动

1. 确定实例 Home 和实际运行账号。默认沿用现有平台路径规则；Windows 通常为 `%LOCALAPPDATA%\modeldb`，服务安装则使用明确的服务账号与实例目录。
2. 对初始化加独占锁，创建实例 ID、受限目录、本机管理通道和安全注册表。
3. 随机生成实例主密钥与必要的独立密钥，使用 SecretProvider 保存。Windows 默认采用当前实际运行账号的 DPAPI 及目录 ACL，不能误用安装时账号导致服务启动后无法解密。
4. 写入不含长期秘密的配置与初始化状态，完成同步和一致性检查后标记实例可用。
5. 默认仅监听 loopback。安装的本机启动器通过受 ACL 限制的 Named Pipe / Unix Socket 证明本机管理身份，向服务申请一次性浏览器配对授权。
6. 启动器打开 Designer。浏览器兑换短期、一次性、绑定目标实例与预期 Origin 的配对授权，服务建立会话。授权不得进入 URL 查询参数、访问日志或长期浏览器存储；前端消费后清理临时地址状态。
7. 安全中心显示“本机安全已初始化”，并单独显示独立恢复材料是否已保存。

全流程不把“第一个访问 HTTP 的客户端”视为管理员。多个浏览器或安装进程竞争初始化时，只有受信本机管理通道可以签发配对授权。

### 4.2 后续启动与异常

正常启动直接解封本机密钥并建立本机配对会话。重启服务不会更换实例身份、数据密钥或 API Token。

以下情况必须明确报错并进入维护状态：DPAPI 无法解封、密钥记录缺失、Vault 认证失败、安全注册表损坏、实例 ID 不匹配。不能自动新建“看起来正常”的空库，也不能生成新密钥覆盖旧密钥。

重装系统、切换服务账号和直接复制整个实例目录，不保证本机保护仍可解封；这类操作走正式迁移或恢复流程。

浏览器单独打开一个地址时，如果没有有效会话，则显示连接或配对页。本机正常安装启动路径可以自动完成配对；开发环境继续手动启动 Vite 时，可以通过本机 CLI 打开配对链接，而不是在前端 `.env` 中放永久管理员 Token。

远程设备首次接入由已有管理员在安全中心批准：先确认目标实例地址、TLS 信任和待授权范围，再生成短时一次性邀请。远程浏览器兑换后获得限定会话，默认不继承实例管理员权限。若需要记住设备，只保存服务端可撤销、绑定该设备且轮换的续期能力；浏览器使用受保护 Cookie，不持有长期全权限 Token。没有任何有效管理员会话时，只能从可信本机通道或恢复流程重新授权，不能开放“无人认领管理员”页面。

### 4.3 恢复材料与自动化的边界

本机初始化可以自动完成，独立恢复材料的保存不强制阻止日常使用。但未保存时，状态必须明确显示“仅具备本机恢复能力，尚未完成异机灾难恢复准备”。

推荐首次配置恢复时生成独立恢复密钥对：本机保留恢复公钥，私钥形成加密恢复包；用户把恢复包和解锁材料保存在独立位置，或交给已配置的外部密钥服务。未来备份和密钥轮换可直接用恢复公钥生成新封装，不需要反复手工输入口令。

新恢复公钥登记后，应为仍需恢复的旧密钥补齐恢复封装；旧备份的历史密钥不能因主密钥轮换而被自动销毁。独立恢复材料更换时，要明确哪些旧包仍依赖旧材料。

若用户没有独立恢复材料，又同时失去系统账号保护和本机密钥，系统无法通过“重置密码”找回加密数据。把恢复包和解锁材料一起放在同一个本机目录，并不能解决整机丢失问题。

## 5. API Token、权限与会话

### 5.1 权限模型

采用“主体 + 数据库 / 资产资源 + 操作范围”的默认拒绝模型。管理接口、通用 RPC、HTTP、WS、批量入口和所有发布接口共用一套授权判断。

| 预设身份       | 默认能力                                                    | 额外授权才具备的能力                           |
| -------------- | ----------------------------------------------------------- | ---------------------------------------------- |
| 实例管理员     | 管理实例、凭证、会话与密钥策略                              | 危险删除、明文导出等仍需具体操作确认与审计     |
| 模型设计者     | 在获授权数据库内管理模型、查询设计和发布版本                | 跨库访问、实例安全管理、数据批量写入及资产交付 |
| 数据操作员     | 在获授权模型内查询和写入数据                                | 模型结构修改、接口发布、密钥与凭证管理         |
| 发布接口调用者 | 调用获授权的 Query / Operation Interface 或 Binding Surface | 通用模型 RPC、系统模型访问、任意字段查询       |

角色只是预设权限集合。导入、数据导出、备份恢复、资产交付分别定义操作权限，避免“可以查到部分数据”隐含“可以整库打包”。V1 不把完整的行级权限、租户隔离策略或复杂企业组织模型纳入首批交付。

发布接口调用者只能访问接口契约允许的字段、条件和操作。服务端不能把调用者传入的任意模型名、字段名、路径或通用 RPC 当成可信指令。发布版本若扩大字段或写入范围，必须重新检查发布者权限，并让维护者看到权限范围变化。

关系 bind / unbind / rebind 检查关系操作及涉及资源的授权；级联删除和间接写入也纳入检查。Operation Interface 的调用权限仅授予执行已发布契约的能力，不自动授予调用者任意模型写权限。

批量请求对每一项授权：事务模式任一项无权限则整批拒绝或回滚；允许部分成功的模式返回逐项结果。不得先执行一部分，再发现权限错误，却仍宣称整批事务成功。

### 5.2 生命周期的建议默认值

| 项目                   | V1 建议默认值                                              |
| ---------------------- | ---------------------------------------------------------- |
| 一次性配对授权         | 60 秒、仅可兑换一次，失败次数受限                          |
| Designer 普通会话      | 空闲 30 分钟、绝对有效期 12 小时；受信本机启动器可重新配对 |
| 管理敏感操作的新鲜授权 | 最近 5 分钟内通过可信本机通道或管理员再验证                |
| 新建 API Token         | 默认 30 天，默认无权限；用户选择数据库和接口后创建         |
| 普通轮换宽限期         | 默认 10 分钟，可选择立即作废旧凭证                         |
| 紧急撤销               | 无宽限期；新请求立即拒绝，相关 WS 会话关闭                 |

有效期、上限与宽限期可配置，但创建页不得默认生成永不过期的全库管理员 Token。自动化客户端使用专用服务凭证，后续可通过受保护密钥代理接入自动轮换。

撤销后的会话、权限缓存和 WS 都必须同步失效。已经进入提交阶段的事务按事务规则完成或回滚，不能为立即断开而制造半写入；排队和后续操作拒绝执行。耗时只读任务在安全取消点停止。

Cookie 使用 HttpOnly、SameSite，并在 HTTPS 场景开启 Secure。本机开发 HTTP 仅允许 loopback 的受控例外，不把该例外推广到局域网。生产推荐同源部署 Designer 与 API；开发 Origin 单独列入白名单。状态变更请求增加 CSRF 验证，WS 检查 Origin 和有效会话。

长期 API Token 不再进入 localStorage、sessionStorage、构建时环境变量或 URL。程序调用使用 `Authorization: Bearer ...`，不使用 Query 参数传 Token。多种认证头冲突时拒绝请求，避免不同入口选取不同身份。

## 6. 传输、限流、日志与本地存储

### 6.1 远程访问

新实例默认本机模式。明确开启远程模式时，支持两种部署：Server 直接提供 HTTPS / WSS；或由受信反向代理终止 TLS，Server 仅开放给代理的本机或受控网络链路。

`publicBaseUrl` 仅表示调用地址，不授予权限、不签发证书。自动 Network 地址可以继续显示，但 IP、域名、证书 SAN 和客户端信任必须匹配。自签名证书的远程首次信任需要指纹确认或预先安装受信根，不能把“忽略证书验证”作为默认方案。

生产模式发现非 loopback 明文开放且没有有效代理隔离配置时，启动检查应拒绝不安全配置并给出修改方法。不得仅因设置了 `publicBaseUrl` 就认定链路已加密，也不得盲目信任来自任意来源的 `X-Forwarded-*`。

新 wire 协议进行版本协商，使用标准序列化与 TLS。旧 XOR 编码不能作为加密层继续宣传；SDK 与 Server 不匹配时明确返回版本错误，不静默降级到旧认证协议。

### 6.2 限流与执行预算

沿用现有发布接口限流能力，并增加认证失败、主体、接口、连接数与请求体等维度。凭证创建、配对和恢复入口使用独立限制，避免它们成为暴力尝试入口。

V1 建议从以下可配置基线开始，再根据验证数据调优：普通请求体 8 MiB、普通批量最多 100 项；大文件导入采用独立流式上传、文件大小限制和导入任务配额。为查询、导出和导入设置执行时间、返回行数或字节数预算；全量任务明确进入受配额限制的任务流程。

认证失败优先按来源与目标入口限流，不能仅凭攻击者反复失败就永久锁定某个合法用户。返回统一错误信息和 `Retry-After`，避免泄露凭证是否存在。V1 单实例内存窗口可接受，重启后的短暂限流窗口丢失需记录；多节点共享配额属于后续扩展。

### 6.3 审计和可观测性

审计至少覆盖初始化、配对、凭证创建/轮换/撤销、权限修改、远程访问变更、密钥维护、备份恢复、资产导入导出和所有写接口。记录主体 ID、资源、操作、结果、时间、请求 ID、来源、耗时和记录数量。

不记录 Token、Cookie、私钥、恢复码、完整查询参数值或业务结果。对开发模式全量查询日志同步整改。普通错误响应只返回稳定错误码和请求 ID；物理路径、栈和底层系统错误进入受限诊断日志，不再直接出现在用户界面。

普通诊断日志允许轮转和保留策略；关键安全管理动作在审计不能可靠持久化时拒绝执行，并暴露健康告警。V1 本地审计提供追踪与受限访问，不声称能够抵抗拥有系统管理员权限的攻击者删除日志；需要此能力时接外部审计存储。

指标至少包括认证失败、拒绝授权、限流命中、活跃会话、接口延迟、导入导出任务、备份成功率和恢复演练状态。指标标签不用 Token ID、原始参数等高基数或敏感信息。

### 6.4 目录、密钥和缓存

实例 Home 是唯一的默认安全目录根，不跟随当前 shell 工作目录变化。逻辑布局如下，文件格式在实现阶段冻结：

```text
<instance-home>/
  modeldb.config.json      非秘密配置与安全存储引用
  security/                实例身份、凭证注册表、策略、受保护密钥封装
  logs/                    脱敏诊断日志
  audit/                   安全事件
  cache/                   可重建缓存，不能作为密钥或恢复材料的唯一存储
```

业务 Vault 可以位于单独配置的工作区；缓存和日志不会因从该工作区启动而自动回落到 Vault 目录。备份文件继续写入仓库约定的 `<workspace>/modeldb/backups/`，外部迁移通过管理面的下载/导入能力完成；本次不顺带修改现有备份根目录规则。启动状态展示各类实际路径，权限不足时报错，不能悄悄改写到另一个目录。

安全注册表独立于业务 Vault 和 Designer 的 `sys_*` 模型，避免“先解密业务库才能认证、先认证才能取密钥”的循环。注册表采用具备事务与崩溃恢复的存储；权限和撤销状态不可因普通业务备份恢复而回滚。

这里的“安全注册表”是引擎维护的身份与凭证台账，不是把资产登记到 Windows 注册表后才能解锁。操作系统绑定只用于保护本机运行密钥；资产包依靠独立接收方或恢复封装实现跨机器交付。仅把当前明文 Token 从 JSON 移到环境变量，也不等于完成安全改造。

Windows 默认使用账号范围的 DPAPI 配合 ACL；其他平台由 SecretProvider 适配系统钥匙串、Secret Service、容器 Secret 或外部密钥服务。容器缺少系统钥匙串时必须显式挂载受保护秘密，不回退到明文配置或环境中固定默认密钥。无人值守 Linux 不能默认依赖需要图形登录才能解锁的钥匙串。

Core 只接收按库解析的密钥提供器，不再读取网络认证 Token。明文数据缓存仅在必要范围存活，退出、撤销敏感会话及密钥维护时按资源失效；落盘缓存含业务数据时同样加密或禁止落盘。任何缓存都不能绕过权限检查，也不能作为导入完整性验证的最终依据。

导入预检可以复用带版本的模型缓存、索引和批量存在性查询来优化性能；真正提交前仍检查数据版本、唯一 ID、关系两端、类型和权限，防止预检之后的数据变化产生错误。继续遵守现有 AuthoringBridge 缓存规则，不用 Vault mtime 作为无条件失效依据；恢复或替换文件时显式关闭并驱逐对应引擎实例。

## 7. 重置与维护必须分成不同操作

| 操作               | 做什么                                         | 对现有数据的影响                                                     |
| ------------------ | ---------------------------------------------- | -------------------------------------------------------------------- |
| 轮换某个 API Token | 创建新凭证，按宽限期撤销旧凭证                 | 不修改数据库密钥或数据                                               |
| 重置全部访问凭证   | 撤销现有 API Token、设备与会话，重新配对管理员 | 保留业务 Vault 和密钥；外部客户端需要重新授权                        |
| 轮换实例主密钥     | 用新 IMK 重新封装 DEK，并更新恢复封装          | 通常不重写业务数据；历史备份仍需可恢复                               |
| 轮换某个数据库密钥 | 生成新 DEK，分阶段重新加密该库                 | 需要写入门禁、进度、可恢复日志和空间预算                             |
| 通过恢复材料接管   | 验证恢复材料，在新环境重新封装数据密钥         | 保留数据，默认撤销旧会话并创建新的实例访问身份                       |
| 恢复出厂设置       | 删除指定实例的数据和安全状态                   | 破坏性操作；明确目标、尽量先创建安全备份、二次确认，CLI 需要 `--yes` |

本机 CLI 不因连接来自 `127.0.0.1` 就允许重置；它通过受保护本机通道验证调用者的 OS 身份。远程安全中心的敏感维护需要新鲜的管理员授权。独立恢复材料允许数据恢复，但不自动恢复源实例的所有管理员身份和信任关系。

如果怀疑只有 API Token 泄露，撤销并审计即可。如果怀疑主密钥或数据库明文已泄露，则应轮换受影响数据密钥并排查备份和交付范围；仅修改 Token 无法追回泄露的数据。

主密钥轮换、DEK 轮换、恢复替换采用任务化状态机：预检、准备、写入、验证、提交、清理。中断后可以确定地恢复，不出现密钥已换而 Vault 未换的状态。需要保留旧密钥时明确原因与保留期限，销毁前检查仍依赖它的备份。

## 8. 备份、移库与资产图谱交易

### 8.1 三种交付物分别处理

| 类型         | 主要目的                                 | 凭证与密钥处理                                                         |
| ------------ | ---------------------------------------- | ---------------------------------------------------------------------- |
| 日常备份     | 在误操作、文件损坏或机器故障后恢复       | 全包加密，包含恢复所需的密钥封装；不包含可直接使用的管理员 Token       |
| 完整受信迁移 | 把一个完整数据库迁到自己控制的另一实例   | 通过迁移包让目标实例重新封装数据库密钥；明确源实例和目标实例的身份变化 |
| 资产交付包   | 出售或分享指定图谱、模型、接口和可选数据 | 为选定内容生成独立包密钥，绝不把源库 DEK 交给买家                      |

迁移只有在完整、受信和明确选择的场景下才考虑封装现有 DEK。资产交易和部分数据导出必须使用新 PEK，否则买家可能利用源 DEK 解锁卖家的其他备份。

Excel 数据导入导出继续服务人工编辑和模板填充；它不是加密资产包、密钥备份或完整系统迁移的替代品。导出 XLSX / CSV 等可读数据必须有独立权限与脱敏选择，并明确文件中包含可读业务数据；其中不导出系统秘密字段或访问凭证。聚合、计算结果可导出为只读报表，继续不支持反算导入。

### 8.2 资产包的内容

允许选择模型结构模板、结构加数据、接口及依赖，或完整资产图谱。清单至少包含格式版本、资产永久 ID、资产版本、来源实例标识、发布者标识、依赖、模型与字段映射、接口契约版本、数据与关系数量、内容摘要、签名和接收方密钥标识。

数据内容保留唯一 ID 与关系路径，便于验证和冲突处理；同时区分“资产永久 ID”和“本地数据库实例 ID”。导入生成新的本地实例 ID，不把买家的实例误认为卖家的原实例。

Query Designer 的发布台账、Binding Surface 等元数据可能保存在单独的 Designer 系统库。打包器必须按资产归属和依赖选择性提取，并映射内部引用；不能为方便而把整个 Designer 系统库、其他资产的接口或用户会话一起导出。

UI 展示、i18n 元信息及接口选中字段随资产依赖打包。原始数据的层级与关系信息必须完整；不把运行结果的扁平表格当成全部关系定义。

### 8.3 导入和恢复流程

1. 检查文件体积、条目数量和格式版本，解析受限清单。
2. 校验接收方、签名、摘要及加密完整性。签名只证明对应私钥持有者签过内容；发布者是否可信，还需要用户信任、已验证指纹或平台信任链。
3. 在隔离暂存区解密和预检，展示模型、字段、数据、关系、接口、冲突以及所需权限。
4. 默认导入为新库；覆盖或合并必须显式选择，并明确 ID 冲突策略。不能静默覆盖同名资产。
5. 写入目标实例保护的新 Vault，验证关系双向完整性与接口依赖，重建索引和非权威缓存。
6. 涉及业务 Vault 与 Designer 系统库的跨存储更新使用持久任务日志和分阶段发布；全部验证完成前不对普通用户开放半成品。没有跨库存储事务时，不宣称已经具备原子跨库事务。
7. 返回逐阶段反馈、统计、错误路径和可重试信息，清理暂存明文；保留脱敏审计。

导入器拒绝路径穿越、绝对路径、符号链接、Windows ADS、重复路径、超限解压、超限 KDF、未知危险扩展和不允许的版本降级。资产包中的内容不作为任意脚本、插件或系统命令执行。

备份读取采用一致性快照或受控写入屏障，关联元数据也有一致版本。恢复前校验备份、恢复权限和密钥可用性；替换业务库时关闭相关引擎与会话，显式驱逐缓存后重新打开。恢复业务备份不能重新激活已撤销 Token 或旧设备会话。

### 8.4 自动备份与交易边界

安全初始化不会暗中开启周期备份，沿用当前“自动备份默认关闭”的规则。用户启用后，备份自动使用独立包密钥并加入实例恢复封装；配置了独立恢复公钥或目标接收方后，再加入相应封装。

本机备份和独立灾备分别显示状态。备份文件不能只依赖某个随时可能轮换的网络 Token。完成备份不等于完成可恢复验证，应提供定期验证与隔离恢复演练。

V1 建设资产交付的技术基础，不包含交易平台、支付、版权裁决或防复制 DRM。买家一旦获得可解密内容，就可能复制数据，密码学不能阻止这一点。需要持续可撤销访问的商品应采用托管 API 订阅；撤销订阅也不能收回买家先前合法下载的数据。

## 9. 安全中心、CLI 和配置

### 9.1 安全中心页面

安全中心采用完整工作页面，保持进入前所选编辑器，返回后恢复原工作上下文。敏感设置不塞入狭窄侧栏；所有长期 UI 文案提供中文、英文和日文。

| 页面区域   | 展示和操作                                                                 |
| ---------- | -------------------------------------------------------------------------- |
| 概览       | 实例 ID、安全模式、实际数据/日志/缓存路径、TLS、本机保护和独立恢复准备状态 |
| 访问凭证   | 名称、范围、到期、状态、最近使用；创建、轮换、撤销；原文仅创建时交付一次   |
| 设备与会话 | 设备、来源、权限、到期；撤销单个设备或全部会话                             |
| 权限       | 角色预设与数据库、模型、接口、数据导出等具体授权                           |
| 密钥与恢复 | 主密钥/DEK 状态与版本、恢复包登记、恢复演练、受控轮换任务                  |
| 网络       | 监听地址、对外调用地址、证书、允许的 Origin、可信代理                      |
| 审计       | 可过滤事件、失败原因与请求 ID；受权限约束的脱敏导出                        |

权限或密钥没有变化时，不通过自动刷新让页面和工具栏反复闪烁。异步任务显示稳定布局、进度和最终结果；敏感明文不出现在通知、剪贴板历史提示或错误堆栈中。

### 9.2 计划提供的 CLI

下列为拟新增命令，当前不能作为现成能力使用。实际参数以实施后的 `--help` 为准。

```powershell
# 普通安装启动自动完成初始化；此命令用于部署和显式预检
modeldb-server security init
modeldb-server security status

# 从本机可信通道打开 Designer 并配对，不打印永久管理员 Token
modeldb-server security open-designer

# 创建只能调用指定 Query Interface 的凭证，原文写入受保护文件
modeldb-server token create --name reporting-client --database railway_domain_v1 --query-interface AdministrativeDivision_Query --expires-in 30d --output-file C:\secure\reporting-client.token

# 列表不返回凭证原文；轮换输出仍使用受保护文件
modeldb-server token list
modeldb-server token rotate TOKEN_ID --grace 10m --output-file C:\secure\reporting-client-next.token
modeldb-server token revoke TOKEN_ID
modeldb-server session revoke --all

# 恢复访问与轮换数据保护密钥分开
modeldb-server security reset-access
modeldb-server security rotate-master-key
modeldb-server security rotate-database-key --database railway_domain_v1

# 生成、验证和使用独立恢复材料；秘密通过交互或受保护文件输入
modeldb-server security recovery-export --output C:\secure\instance.recovery
modeldb-server security recovery-check --file C:\secure\instance.recovery
```

输出文件示例目录需预先具备正确 ACL；CLI 对不安全目录和覆盖已有文件进行检查。默认不把秘密打印到日志或终端，不鼓励将秘密直接写在参数里。恢复包的解锁材料与包分开保存，不能因为同时写到同一目录就宣称完成独立灾备。

### 9.3 计划中的配置形态

以下 JSONC 用于解释新结构，不是当前版本可直接加载的配置，也不要求用户安装后手写。配置生成器应自动提供默认值，现有非安全配置另行保留。

```jsonc
{
  "port": 9091,
  "host": "127.0.0.1", // 默认只允许本机网络连接
  "publicBaseUrl": "", // 仅用于展示对外调用地址，不代表 TLS 或授权
  "security": {
    "mode": "local", // 开启远程访问时需通过远程安全预检
    "secretProvider": "auto", // 按运行环境选择系统保护；不可用时不回落到明文
    "session": {
      "idleTimeoutMinutes": 30,
      "absoluteLifetimeHours": 12,
    },
    "apiToken": {
      "defaultExpiresInDays": 30,
      "rotationGraceMinutes": 10,
    },
    "browser": {
      "allowedOrigins": [], // 生产同源由部署信息确定，额外 Origin 必须明确登记
    },
    "remote": {
      "enabled": false,
      "tls": { "mode": "disabled" }, // 仅限本机模式；远程需 direct 或受信代理模式
      "trustedProxies": [],
    },
  },
  "autoBackup": {
    "enabled": false, // 安全初始化不替用户决定周期备份与外部保存位置
    "intervalMs": 60000, // 沿用现有最小调度间隔；未启用时不会开始定时备份
  },
}
```

配置中不出现 `connectToken`、Vault 解密密码、恢复码或私钥原文。必要证书、容器 Secret 和外部密钥服务通过文件/提供器引用接入，并检查权限。

| `packages/shared`     | 浏览器兼容的协议、权限/会话契约、版本与稳定错误码；不包含本机密钥实现          |
| `packages/sdk`        | 新认证与协议、TLS 校验、过期/撤销错误、凭证更新钩子；保持远程客户端边界        |
| `apps/model-designer` | 本机配对、短期会话、安全中心、权限可见性、完整 i18n 和工作区返回状态           |
| 数据传输模块          | 资产依赖收集、包清单、独立加密/签名、导入预检和完整反馈                        |
| 文档与测试            | 替换互相冲突的旧安全说明，生成新配置注释、操作手册和故障恢复演练               |

### 10.2 按依赖推进的七个阶段

| 阶段                             | 实际交付                                                                                       | 阶段验收                                                                  |
| -------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| S1：密钥与 Vault 基础            | 冻结威胁边界、格式和密钥提供器契约；实现独立 IMK / DEK、Windows 本机保护、旧格式识别与安全写入 | Token 不再参与 Vault 解密；错误密钥、断电与写入失败不覆盖有效库；重启可读 |
| S2：实例身份与凭证生命周期       | 独立安全注册表、本机管理通道、自动初始化、API Token 创建/轮换/撤销、CLI                        | 无明文配置秘密；本机 TCP 不能冒充管理员；撤销持久且重启后仍生效           |
| S3：全入口统一授权               | HTTP / WS / bulk / 发布接口共用权限检查；模型、关系、导出及系统资源边界                        | 限权接口凭证无法转为任意模型查询；批量和关系操作无越权路径                |
| S4：安全传输与自动 Designer 会话 | HTTPS/WSS、可信代理、Origin/CSRF、新 SDK/wire、本机启动器配对                                  | 安装后本机无需复制 Token；远程不明文传秘密；前端构建和存储无长期 Token    |
| S5：安全中心、限流与审计         | 完整页面、设备/凭证管理、敏感操作再验证、配额、脱敏审计和健康指标                              | UI/CLI 行为一致；限流可解释；事件可归因；管理失败不出现秘密或完整路径     |
| S6：恢复、备份和可迁移资产       | 独立恢复材料、历史密钥管理、完整包加密与签名、资产依赖导入导出                                 | 异机恢复成功；业务恢复不复活旧凭证；买家包不能解密源库其他数据            |
| S7：发布前验证与交付             | 故障注入、回归、安装/重装/账号变化演练、性能对比、文档与配置同步                               | 满足下方发布门槛，能够重现本机使用、远程调用、重置、移库和灾备全过程      |

S1、S2 是基础，S3 依赖凭证主体，S4 接入浏览器与 SDK，S5 提供维护入口，S6 建立恢复与资产交付，S7 集成验收。每阶段保留可审查结果，不把所有安全变更堆到最后一次大切换。

独立恢复的格式和职责在 S1 就要确定，避免 S6 才发现早期密钥不可恢复。S6 完成前，可以对新格式做研发验证，但不把它宣称为已经具备异机灾备的正式发布版本。TLS 和授权未同时完成前，也不对远程开放新的管理入口。

Windows 是当前首要验证平台。其他平台要分别完成 SecretProvider 与无人值守启动验证后，才能列入受支持部署；不会把 Windows DPAPI 实现直接宣称为跨平台安全支持。

## 11. 正式收尾的验收清单

- 全新实例无需编辑秘密配置，通过本机启动器可以自动进入 Designer；普通 HTTP 客户端无法抢占管理员。
- 重启、并发首次启动和初始化中断后，实例 ID、凭证与数据密钥一致，不出现重复实例或空库覆盖。
- Token 轮换后 Vault 内容无需重加密；新旧凭证宽限期、过期和紧急撤销符合契约。
- 已撤销凭证在 HTTP、现有 WS、批量入口和进程重启后均不可继续执行新操作。
- 发布接口调用者不能访问未选中字段、其他数据库、通用 RPC 或系统管理模型；关系与间接写入检查完整。
- 密钥缺失、认证标签错误、文件损坏、磁盘空间不足和提交中断时保留可恢复状态，不悄悄重建库。
- 主密钥轮换、DEK 轮换与访问重置分别验证；旧备份在约定历史密钥保留期内仍可恢复。
- 远程 HTTPS/WSS、证书错误、Origin/CSRF、可信代理与代理伪造分别验证；无静默不安全降级。
- 浏览器存储、前端产物、配置、日志、错误、指标和审计导出均不含长期凭证、私钥或恢复码。
- 新机器在没有源机器 DPAPI、没有旧 Token 的情况下，仅凭正式恢复材料可恢复备份。
- 资产交付包包含选定模型、原始数据、关系、接口、版本和 i18n；不混入其他图谱或源实例秘密。
- 资产篡改、未知签名者、ID 冲突、路径攻击、超限解压及恶意 KDF 有明确处理和反馈。
- 恢复普通业务备份不回滚安全注册表，不复活已撤销的会话与凭证。
- 模型设计、Query / Operation Interface、Binding Surface、分页、Pivot 预览、Excel 导入导出和备份已有流程回归通过。
- 测量查询、批量写入、导出与启动的开销，区分 TLS、权限和 Vault 加密成本，依据结果调优，不预先承诺零性能影响。
- 安全中心、CLI 帮助、默认配置、安装指南和故障恢复说明一致，长期 UI 文案覆盖 zh / en / ja。

## 12. 本方案的实施边界

V1 要交付默认安全初始化、独立认证与加密、最小权限调用、可撤销会话、维护重置、可验证备份、独立恢复和可迁移资产包。市场交易平台、企业 SSO、硬件密钥、KMS 多节点高可用、复杂行级授权和 DRM 为后续扩展。

当前下一项研发应从 S1 开始，先完成密钥解耦和新 Vault 基础；不能先给现有 `connectToken` 增加轮换按钮就称完成安全改造。实际切换旧环境前，应形成明确的库清单和新格式验证结果，再执行用户明确授权的重建或迁移操作。
