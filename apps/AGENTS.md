# 前端页面开发约定

适用于 `apps/` 下所有前端应用。开始新页面开发或旧页面改造前，必须读取本文件和所在应用的 `AGENTS.md`（若存在）；接续会话同样适用。安全改造还需读取 `docs/security-v1/AGENTS.md`、唯一台账与最新交付记录。

## 页面美观

- 新页面开发与旧页面改造都必须考虑页面美观，作为交付要求。
- 复用所在应用已有的主题、组件、字体、间距、配色与交互风格，保持清楚的内容层级、对齐和操作主次；避免局部改造破坏整体视觉一致性。
- 覆盖正常、加载、空白、错误、禁用及操作反馈状态，检查窄屏、长文案、键盘焦点和可读性。涉及可见布局或样式时，使用隔离页面实际检查，不以类型检查代替视觉验证。
- 改造范围围绕本次任务，保留无关的既有页面和用户改动；不借美化进行无关重构。

## i18n

- 新页面开发与旧页面改造都必须考虑 i18n，复用所在应用的语言管理和翻译机制。
- 用户可见标题、按钮、提示、错误、占位符、无障碍标签和动态状态使用翻译键；新增及修改文案同步现有支持语言，Designer 和 Data Studio 为 `zh/en/ja`。其他应用按已有语言矩阵执行，不把未支持语言声称为已完成。
- 日期、数字等按已有本地化规则展示；不改变库名、协议标识、错误码和原始业务值。检查切换语言、较长翻译和缺失键回退，避免截断、溢出或显示翻译键。
- 页面交付报告说明美观与 i18n 的检查范围、实际结果和未验证项；仅逻辑修改且没有界面/文案变化时明确记录即可。
