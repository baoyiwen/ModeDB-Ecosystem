# Model Designer 操作手册

本文面向产品、测试、实施、非核心开发和首次接手该模块的同学，重点描述“如何连接、如何打开、如何编辑、如何保存、如何排查”。

## 1. 进入模块前需要准备什么

你需要确认以下信息：

- `host`
- `port`
- `connect token`
- 目标业务库名称

还需要确认：

- ModeDB Server 已经启动
- 设计器专属库允许自动创建
- 目标业务库已经存在，或者准备通过连接页创建

## 2. 启动方式

在仓库根目录执行：

```bash
pnpm --filter model-designer dev
# 或
pnpm dev:model-designer
```

Vite dev server 已绑定 `host: true`（监听所有网卡），启动后终端会同时打印两类地址：

- **Local**：`http://localhost:5175/`，本机使用。
- **Network**：`http://<开发机局域网 IP>:5175/`，同一局域网内的其它设备（手机 / 平板 / 另一台电脑）用它打开。

浏览器打开任一地址后，会先看到连接页。首次监听所有网卡时，Windows 防火墙可能弹窗，需要放行 `5175` 端口，其它设备才能访问。

## 3. 连接流程

### 3.1 填写连接参数

在连接页输入：

- 主机地址
- 端口
- token

可选：

- 勾选“记住 Token”

注意：

- “记住 Token”用于预填表单
- 刷新后自动重连依赖的是 session token，不完全等价于“记住 Token”

跨设备访问时的主机地址（重要）：

- 从**另一台设备**用 Network 地址打开设计器时，连接页里的主机 **不能填 `127.0.0.1` / `localhost`**——那指向设备自身，连不到开发机上的引擎。
- 请填开发机的**局域网 IP**（例如 `192.168.x.x`）与引擎端口（默认 `9090`），并确认引擎 server 也监听了局域网（见 §2 与根目录 `pnpm start:server:network`）。
- 也可在启动 dev server 前设置 `VITE_MODE_DB_HOST=192.168.x.x`，让连接页默认主机直接指向局域网引擎，免去每台设备手填。

### 3.2 列出并选择业务库

点击“列出逻辑库并继续”后，系统会：

1. 调用 `listDatabases`
2. 确保设计器专属库存在
3. 初始化设计器 catalog
4. 拉取逻辑库列表

此时你可以：

- 选择已有业务库
- 创建新业务库
- 编辑逻辑库展示名称与描述

## 4. 进入画布后能做什么

画布上的浮动工具按钮按功能分为四个区域：左侧竖排为模式切换，左上角为视图与保存，右上角为数据库管理，底部中间为画布布局。

### 4.1 左侧工具栏（模式切换）

- 选择模式
- 新增模型模式
- 删除模式
- 连线模式

部分按钮当前仍是占位或只读态，例如“编辑”“多选”。

### 4.2 左上角工具组（视图与保存）

浮层左上角集中放置视图与保存/拉取类操作：

- 平移、搜索、撤销、重做（部分为占位/敬请期待）
- 保存：将当前设计器图与业务库 catalog 对齐后，推送到设计器专属库
- 拉取：从业务库重新读取 catalog 并刷新画布

### 4.3 右上角工具组（数据库管理）

浮层右上角集中放置当前业务库的管理入口（详见第 9 节）：

- 备份、恢复、导出、导入、清除数据、重置数据

右上角落仍保留“断开连接”按钮，工具组已做偏移避让，不会与其重叠。

### 4.4 底部中间工具组（画布布局）

浮层底部中间放置画布显示与布局开关：

- 力导向布局
- 吸附与对齐
- 点阵网格

### 4.5 右侧侧栏

根据当前状态显示：

- 模型信息
- 字段列表
- 关系详情
- 图层结构
- 通知中心
- 设置面板

### 4.6 模型目录（Model Map）

点击画布左下角面板工具组中的“模型目录（Model Map）”图标，进入当前数据资产图谱的全屏模型目录。全部模型在同一大页面中以手风琴形式排列，默认展开，通过鼠标滚轮连续浏览。点击模型标题可平滑收起或展开简介和字段表，允许多个模型同时展开；顶部提供“全部展开 / 全部收起”和搜索。展开与收起带有高度、淡入淡出和箭头旋转动画，遵循系统的减少动态效果设置。

- 支持按模型名、字段名、唯一名和简介搜索；匹配的字段会高亮，字段表仍保留模型的完整字段。
- 输入搜索词时自动展开模型，方便查看匹配的字段。
- 名称、简介和数据类型随当前界面语言展示，模型与字段的唯一名另行保留。
- 字段表包含数据类型、简介、必填、主键及定义来源；继承字段去重展示，点击来源可直接滚动到对应模型。字段表完整展开，窄屏可横向滚动查看各列。
- 目录为只读视图，使用当前图谱中的模型定义（含尚未保存的修改），不会查询业务数据或添加数据库隐藏字段。
- 点击“导出 Excel”下载 `.xlsx` 文件，按当前语言导出整个图谱，不受搜索或收起状态影响。第一个工作表为模型信息表，集中列出各模型的名称、唯一名、简介、父模型、字段数量及对应字段工作表名称。其余工作表使用模型唯一名命名，仅包含该模型的完整字段表（包含去重后的继承字段和来源），不再重复模型基本信息。所有数据表均提供表头筛选和冻结窗格。Excel 不允许的字符、过长名称和重名会自动处理，原始唯一名和实际工作表名在首表中完整对应。
- 点击关闭或按 Escape 返回原编辑器，不改变当前编辑器模式或画布选择。

## 5. 常见操作

### 5.1 新建模型

1. 点击左侧“新增模型”
2. 在画布空白处点击或双击
3. 选中新模型后，在右侧补充：
   - 唯一名
   - 展示名
   - 描述
   - 颜色
   - 所属页面

### 5.2 新建关系

1. 切换到连线模式
2. 从源模型发起连线
3. 连接到目标模型
4. 在右侧关系详情中补充名称、描述和方向信息

关系操作规则：

- 模型唯一名全局唯一；关系唯一名只在一组端点模型之间局部唯一。
- 例如 `A -> B` 可以叫 `children`，`C -> D` 也可以叫 `children`。
- 自关联关系按单个模型形成自己的局部命名空间，例如 `A.children` 与 `B.children` 可以同时存在。
- 修改模型显示名、模型唯一名、关系显示名或关系唯一名时，不应断开已有关系；关系应被视为一条可重命名的实体。
- 正向关系和逆向关系各自维护唯一名、显示名、描述与基数侧；层级页属于这条关系的公共信息。
- “允许自己绑定自己”默认关闭，只在确实需要实体自己关联自己时开启。

### 5.3 编辑字段

在模型被选中时，字段面板中可编辑：

- 字段名
- 字段类型
- 是否必填
- 展示名
- 字段描述

常见动作：

- 单行快速编辑基础字段信息
- 点击详情图标展开高级信息
- 新增字段
- 删除字段
- 拖拽调整字段顺序

### 5.4 保存设计

点击底部“保存”后，系统会：

1. 读取当前业务库 catalog
2. 将 catalog 导入设计器专属库
3. 生成 `MldgDocument`
4. 推送 `sys_designer_graph` 快照

保存成功后，通知区会有相应提示。

### 5.5 拉取设计

点击底部“拉取”后，系统会：

1. 读取业务库 catalog
2. 导入设计器专属库中的模型/关系目录
3. 重新加载画布

如果本地画布有未保存修改，拉取后的结果会覆盖当前可视状态。

### 5.6 层级页与页模式

层级页用于把模型、字段和关系组织到不同业务视图中。

关键规则：

- 所有模型和关系默认属于主页 `Main`。
- 只有打开层级面板或进入页模式后，层级高亮、置灰与显隐权重逻辑才生效。
- hover 普通页面时，页面内模型和关系高亮，页面外对象置灰；hover `Main` 不联动画布对象。
- 进入页模式后会自动打开层级面板，并进入拾取模式。
- 在页模式下点击画布模型或关系，会在当前选中页中加入或移除该对象；`Main` 页面不可手动编辑。
- 当两个端点模型都被放入同一个页面时，这两个模型之间的所有关系会自动加入该页面；移除端点模型时也会同步更新自动关系归属。
- 显隐按权重计算：对象默认在 `Main` 权重为 1；每多属于一个可见页面权重加 1；只剩 `Main` 时显示主页灰色；所有所属页面都隐藏后对象消失。

### 5.7 数据库基本信息

设置面板中的数据库基本信息用于维护 `sys_data_asset_map`：

- 展示规则为 `显示名[数据库名]`。
- 没有当前语言展示名时，只显示数据库名。
- 保存应更新同一个 `code` 对应的记录，不能每次保存都新增一行。
- 如果历史数据中存在重复 `code`，系统会优先保留信息更完整的一条并清理重复登记。

## 6. 数据清理

### 6.1 清空单模型数据

在模型信息面板底部可执行：

- 清空该模型对应的业务数据

注意：

- 只清业务行数据
- 不删模型定义
- 不删关系定义

### 6.2 清空整库数据

在设置面板中可执行：

- 清空当前逻辑库中的全部行数据

注意：

- 只清数据
- schema 仍保留

## 7. 常见问题

### 7.1 连不上服务

优先检查：

- host 是否正确
- port 是否正确
- token 是否正确
- 服务端是否启动

### 7.2 打开后没有模型

可能原因：

- 业务库本身为空
- catalog 拉取失败
- 设计器专属库初始化失败

建议先看浏览器控制台和通知中心。

### 7.3 保存后刷新丢失

重点检查：

- 是否真的点击过保存
- 保存时是否报错
- `sys_designer_graph` 是否成功写入
- 是否在刷新前执行了拉取覆盖本地状态

### 7.4 字段或关系显示不完整

可能原因：

- 业务库 catalog 当前只返回了简化字段目录
- 某些字段细节还未在 server catalog 接口中暴露
- 设计器侧历史数据与当前导入逻辑不完全对齐

## 8. 推荐操作习惯

- 每次大改前先拉取一次
- 批量调整后及时保存
- 不要把设计器专属库当业务库使用
- 不要直接手改 `sys_*` 行数据，除非你清楚导入与同步链路

## 9. 数据库备份与恢复入口

模型设计器**右上角工具组 → 备份管理**打开独立的全屏管理页面，关闭后保留原来的编辑器：

- 左侧按数据资产图谱（`sys_data_asset_map.code`）分组，展示多语言图谱名和备份数量。归属以备份内容中的 `database` 为准，未登记的历史图谱也保留独立分组。
- **创建备份**：可自行填写名称（1-120 个字符，支持中文），默认名称为 `图谱标识_YYYY-MM-DD-HH-mm-ss`。默认名称和创建时间均按浏览器本地时区显示，精确到秒。
- 名称保存在备份内容的可选 `name` 字段中；服务器文件名仍使用安全唯一标识。旧文件不需要迁移，界面会按图谱与本地创建时间生成展示名，完整文件名可在选中后查看。
- **恢复选中备份**：恢复到该分组对应的图谱，确认框明确展示目标图谱；恢复前 server 会尽量创建安全备份。
- **导出备份文件**：选中备份后下载为 `*.modeldb-backup.json`，保留自定义名称，可用于离线保管或服务器迁移。
- **导入备份文件**：上传并校验本地备份，仅加入原图谱对应分组，不再自动覆盖当前库。需要恢复时另行选中并确认。
- 列表支持按名称、服务器文件名和本地创建时间搜索，以及刷新。
- 设计器专属元数据库不属于业务图谱分组，不在本页提供恢复入口；导入此类备份只保留服务器文件，不自动恢复，可通过运维工具管理。

工具组中另外保留以下当前业务库操作：

- **管理清除数据**：清除当前业务库行数据，保留模型和关系定义。
- **强制重置库**：用于数据库文件损坏时的后门恢复，会重建物理库。

备份页的操作目标以选中的图谱分组为准；清除和强制重置仍仅针对当前业务库。当前图谱恢复、清除或强制重置后，设计器会重新拉取业务库 catalog 并刷新画布。

迁移时先在源服务器创建并导出备份，再连接目标服务器导入，最后在原图谱分组下选择恢复。跨库改名恢复仍可通过 SDK management API 完成；页面不默认进行跨图谱覆盖。

## 10. Operation Designer

从右下角“接口管理器”进入 Operation Designer。当前可设计单记录
`create / update / delete / upsert` 和单关系对 `bind / unbind / rebind` 接口：

- 选择目标模型和可写字段，字段会映射为外部调用参数。
- `update / delete` 自动要求调用方传入记录 `id`。
- `upsert` 可将一个或多个写入字段标记为匹配字段；首次调用创建记录，后续相同匹配值更新原记录。
- `bind / unbind` 自动生成 `sourceId / targetId` 参数，并按关系注册顺序定位两端模型。
- `rebind` 自动生成 `sourceId / previousTargetId / nextTargetId`，source 保持不变；新边建立失败时恢复旧边。
- 继承边不可作为业务关系操作目标；发布执行使用稳定的 engine forward/reverse 名称。
- 可配置返回记录、记录引用、操作摘要或无返回值。
- 可使用连接认证、接口专属密钥、停用外部调用和固定窗口限流。
- 保存草稿后在资产页发布；active release 可直接填写参数并通过真实 SDK 链路在线调试。
- 资产页版本台账会显示历史 release 相对当前版本的兼容性级别。选择“回滚到此版本”后，Designer 会先迁移旧契约并重新编译，再发布一个更高的新版本；当前 release 与设计草稿都会保留。

`batch` 将同一种单项操作应用到 `items` 数组。可设置 1-1000 的最大项数，并选择：

- `continue`：单项失败后继续，最终可能返回 `partial`。
- `stop`：首项失败后停止，未尝试项计入 `skippedCount`。

batch 当前是非原子事务：每个成功项会独立提交，不支持跨项回滚。结果摘要固定返回
`status / requestedCount / attemptedCount / successCount / failureCount / skippedCount`；启用逐项结果后，
还会返回带原始索引、成功状态、影响数量、记录引用或结构化错误的 `items`。

## 11. Query Designer：查询链与分页

### 11.1 继承子模型的选择

查询链上，继承子模型和父模型视为同一个节点：

- 已经选择父模型后再选择它的子模型，不会新增节点，而是把当前节点切换为子模型身份，此后可以使用子模型独有的字段和关系。
- 继承连线不会出现在“下一步可选关系”中，点击继承连线等同于选择该子模型。

### 11.2 分页设置

分页设置位于查询路径区域下方，确定查询链（至少选中一个模型）后才显示：

1. 勾选“启用分页”，默认每页 20 条，按偏移量（offset）分页。
2. 在“默认每页数量”中修改每页返回条数。
3. 取消勾选即恢复为不分页（默认状态）。

条件编辑区不再提供分页设置。设计器界面只提供 offset 模式和默认每页数量；cursor 模式和最大每页数量不在这里设置。已有接口如果原本是 cursor 模式，重新勾选“启用分页”会改为 offset。

## 12. 数据透视（Pivot）

数据透视用于查看业务库中的真实数据结果，从模型详情或已发布查询接口的“查看数据”入口打开全屏窗口。
点击“返回上一页”或关闭数据透视，会返回来源页面；从接口管理器进入时会回到该接口卡片，并保留当前选择的模型 / 查询编辑器。

### 12.1 选择数据源

- **模型数据**：选择当前业务库中的模型，执行该模型的查询（包含关联数据）。
- **查询接口**：选择已发布的查询接口。只列出带 published release 的接口，非 active 状态的接口不可选。根据已发布定义自动生成参数表单，展示类型、必填状态、默认值和对应字段。数字、布尔、日期和 JSON 等输入会先做格式校验；专属密钥在密码框中填写。

进入后默认以表格展示；模型和输入已齐全的接口自动查询。接口缺少必填参数或专属密钥时先等待填写，再点击“刷新”。修改参数后也使用“刷新”更新结果，不会每次输入都发起请求。查询前必须已打开业务库，否则会提示“当前没有打开业务库”。

顶部以单行展示接口名称、版本和业务库。“参数与条件”默认只展示数量摘要，点击展开后可查看固定条件、参数条件和 AND / OR 层级，关联条件与聚合后条件也会保留；缺少必填参数或专属密钥时默认展开输入区。固定条件自动生效，不能在预览中临时修改；需要调整时回到 Query Designer 编辑并重新发布。参数留空时不发送该参数，由接口执行时处理默认值；可选参数留空不代表一定跳过对应条件。导出说明也可按需展开。

### 12.2 查看结果

- **视图**：默认表格；可切换到按记录展开对象和数组的层级视图，或查看数据源原始行的 JSON 视图。重新打开窗口或切换数据源时恢复为表格。
- **语言**：`current` 按当前界面语言显示多语言字段，`raw` / `all` 保留原始多语言对象。
- 表头按当前语言显示模型字段名称；第一列的箭头用于展开关联记录，不再额外占用关系列。子表用缩进和本地化标题区分层级，收起后恢复连续父表。日期显示为 `yyyy-mm-dd hh:mm:ss`，保留来源时区，原始视图不改值。
- 结果下方的固定栏显示返回行数和分页状态。模型默认不分页，可用开关启用；接口按照已发布版本的分页配置运行。支持每页数量、上一页 / 下一页、当前页及服务端返回的总数；修改条件后刷新会回到第一页。分页开关和翻页不会改变顶部工具栏及结果区的高度，窄窗口下分页控件可横向滚动。
- 接口信息、条件、刷新与导出、视图与语言切换固定在结果区上方；字段加载、查询状态、待刷新提示、错误与导出反馈统一放在底部固定状态栏，不会插入顶部使表格上下跳动。刷新按钮保持固定文字和宽度，以图标转动表示查询中。浏览数据时只有结果区统一横向、纵向滚动，主表和各级子表不再出现内部滚动条；超长的展开配置限制在工具栏内滚动，仍保留结果区空间。当前表头在工具栏下方吸顶，进入下一张子表或后续父表时接替显示对应表头。横向滚动条位于结果区底部，表头与数据文字均垂直居中。同条件、同页刷新保留表格的展开状态，刷新失败时保留上次成功结果并明确提示。

注意：

- 查询接口的结果只包含接口投影的字段，数据透视不会绕过接口去读取被隐藏的数据库字段。
- release 版本、限流和服务端错误规则在数据透视中同样生效。
- 专属密钥仅用于当前预览调用，不持久化；切换接口或发布版本后重新填写。
- 未配置分页的接口不会临时添加分页，需要在 Query Designer 修改并重新发布。

### 12.3 模型数据导入 / 导出（第一阶段）

模型“查看数据”窗口中直接提供查询条件、导出 Excel 和下载空白模板。默认无条件；支持且 / 或、等于 / 不等于、包含、数值 / 日期比较和范围、为空 / 不为空。输入控件随字段类型变化，多语言字段可选查询语言。相邻的“且”先成组，再以“或”连接。编辑后点击“刷新”应用，条件不完整会阻止查询和导出。

预览与导出共用条件，导出时会先刷新预览；查询失败会停止导出。模型导出包含全部匹配记录，不限于当前预览页，最多 10,000 条。默认包含关系数据，可取消只导出模型记录。Excel 保留原始 ID、完整多语言值和关系引用，提供表格边框、筛选与隔行底色，辅助键默认隐藏；日期使用可读文本并保留毫秒和时区。空白模板不受查询条件影响。

展开同页的“导入预检”，选择系统导出的 Excel 或填写后的模板，查看新增候选、已存在 ID、关系和问题数量，下载带工作表 / 行 / 字段位置的 JSON 报告，不再打开第二层弹窗。预检不会写入或覆盖数据库。模型入口每次处理一个模型，正式导入提交将在后续阶段提供。限制与文件契约见 [数据导入导出计划](data-transfer-v1.md)。

### 12.4 查询接口导入 / 导出

接口“查看数据”中提供“导出当前结果 Excel”“下载空白模板”和“导入预检”。导出先刷新当前参数，然后按模型分 sheet；仅导出接口返回的结果，分页接口仅包含当前页。原始多语言值完整保留，不会补查接口以外的字段。文件保留接口和版本、返回的原始 ID、关系方向以及 `_paths` 查询路径，可表达同模型多路径和自关联。

如果返回结果缺少原始 ID，或属于聚合 / 派生结果，下载的是只读报表，不能回导；聚合接口不提供空白回导模板。普通接口的空白模板不执行查询。导入预检会验证来源接口 / 版本与字段范围，并结合最新业务库检查类型、ID 和关系约束；结果与问题报告直接显示在当前页面，当前尚不提交数据库写入。
