# Model Designer 操作手册

本文面向产品、测试、实施、非核心开发和首次接手该模块的同学，重点描述“如何连接、如何打开、如何编辑、如何保存、如何排查”。

## 1. 进入模块前需要准备什么

你需要确认以下信息：

- `host`
- `port`
- `connect token`
- 目标业务库名称

还需要确认：

- ModeDB Server 已经启动
- 设计器专属库允许自动创建
- 目标业务库已经存在，或者准备通过连接页创建

## 2. 启动方式

在仓库根目录执行：

```bash
pnpm --filter model-designer dev
# 或
pnpm dev:model-designer
```

Vite dev server 已绑定 `host: true`（监听所有网卡），启动后终端会同时打印两类地址：

- **Local**：`http://localhost:5175/`，本机使用。
- **Network**：`http://<开发机局域网 IP>:5175/`，同一局域网内的其它设备（手机 / 平板 / 另一台电脑）用它打开。

浏览器打开任一地址后，会先看到连接页。首次监听所有网卡时，Windows 防火墙可能弹窗，需要放行 `5175` 端口，其它设备才能访问。

## 3. 连接流程

### 3.1 填写连接参数

在连接页输入：

- 主机地址
- 端口
- token

可选：

- 勾选“记住 Token”

注意：

- “记住 Token”用于预填表单
- 刷新后自动重连依赖的是 session token，不完全等价于“记住 Token”

跨设备访问时的主机地址（重要）：

- 从**另一台设备**用 Network 地址打开设计器时，连接页里的主机 **不能填 `127.0.0.1` / `localhost`**——那指向设备自身，连不到开发机上的引擎。
- 请填开发机的**局域网 IP**（例如 `192.168.x.x`）与引擎端口（默认 `9090`），并确认引擎 server 也监听了局域网（见 §2 与根目录 `pnpm start:server:network`）。
- 也可在启动 dev server 前设置 `VITE_MODE_DB_HOST=192.168.x.x`，让连接页默认主机直接指向局域网引擎，免去每台设备手填。

### 3.2 列出并选择业务库

点击“列出逻辑库并继续”后，系统会：

1. 调用 `listDatabases`
2. 确保设计器专属库存在
3. 初始化设计器 catalog
4. 拉取逻辑库列表

此时你可以：

- 选择已有业务库
- 创建新业务库
- 编辑逻辑库展示名称与描述

## 4. 进入画布后能做什么

画布上的浮动工具按钮按功能分为四个区域：左侧竖排为模式切换，左上角为视图与保存，右上角为数据库管理，底部中间为画布布局。

### 4.1 左侧工具栏（模式切换）

- 选择模式
- 新增模型模式
- 删除模式
- 连线模式

部分按钮当前仍是占位或只读态，例如“编辑”“多选”。

### 4.2 左上角工具组（视图与保存）

浮层左上角集中放置视图与保存/拉取类操作：

- 平移、搜索、撤销、重做（部分为占位/敬请期待）
- 保存：将当前设计器图与业务库 catalog 对齐后，推送到设计器专属库
- 拉取：从业务库重新读取 catalog 并刷新画布

### 4.3 右上角工具组（数据库管理）

浮层右上角集中放置当前业务库的管理入口（详见第 9 节）：

- 备份、恢复、导出、导入、清除数据、重置数据

右上角落仍保留“断开连接”按钮，工具组已做偏移避让，不会与其重叠。

### 4.4 底部中间工具组（画布布局）

浮层底部中间放置画布显示与布局开关：

- 力导向布局
- 吸附与对齐
- 点阵网格

### 4.5 右侧侧栏

根据当前状态显示：

- 模型信息
- 字段列表
- 关系详情
- 图层结构
- 通知中心
- 设置面板

## 5. 常见操作

### 5.1 新建模型

1. 点击左侧“新增模型”
2. 在画布空白处点击或双击
3. 选中新模型后，在右侧补充：
   - 唯一名
   - 展示名
   - 描述
   - 颜色
   - 所属页面

### 5.2 新建关系

1. 切换到连线模式
2. 从源模型发起连线
3. 连接到目标模型
4. 在右侧关系详情中补充名称、描述和方向信息

关系操作规则：

- 模型唯一名全局唯一；关系唯一名只在一组端点模型之间局部唯一。
- 例如 `A -> B` 可以叫 `children`，`C -> D` 也可以叫 `children`。
- 自关联关系按单个模型形成自己的局部命名空间，例如 `A.children` 与 `B.children` 可以同时存在。
- 修改模型显示名、模型唯一名、关系显示名或关系唯一名时，不应断开已有关系；关系应被视为一条可重命名的实体。
- 正向关系和逆向关系各自维护唯一名、显示名、描述与基数侧；层级页属于这条关系的公共信息。
- “允许自己绑定自己”默认关闭，只在确实需要实体自己关联自己时开启。

### 5.3 编辑字段

在模型被选中时，字段面板中可编辑：

- 字段名
- 字段类型
- 是否必填
- 展示名
- 字段描述

常见动作：

- 单行快速编辑基础字段信息
- 点击详情图标展开高级信息
- 新增字段
- 删除字段
- 拖拽调整字段顺序

### 5.4 保存设计

点击底部“保存”后，系统会：

1. 读取当前业务库 catalog
2. 将 catalog 导入设计器专属库
3. 生成 `MldgDocument`
4. 推送 `sys_designer_graph` 快照

保存成功后，通知区会有相应提示。

### 5.5 拉取设计

点击底部“拉取”后，系统会：

1. 读取业务库 catalog
2. 导入设计器专属库中的模型/关系目录
3. 重新加载画布

如果本地画布有未保存修改，拉取后的结果会覆盖当前可视状态。

### 5.6 层级页与页模式

层级页用于把模型、字段和关系组织到不同业务视图中。

关键规则：

- 所有模型和关系默认属于主页 `Main`。
- 只有打开层级面板或进入页模式后，层级高亮、置灰与显隐权重逻辑才生效。
- hover 普通页面时，页面内模型和关系高亮，页面外对象置灰；hover `Main` 不联动画布对象。
- 进入页模式后会自动打开层级面板，并进入拾取模式。
- 在页模式下点击画布模型或关系，会在当前选中页中加入或移除该对象；`Main` 页面不可手动编辑。
- 当两个端点模型都被放入同一个页面时，这两个模型之间的所有关系会自动加入该页面；移除端点模型时也会同步更新自动关系归属。
- 显隐按权重计算：对象默认在 `Main` 权重为 1；每多属于一个可见页面权重加 1；只剩 `Main` 时显示主页灰色；所有所属页面都隐藏后对象消失。

### 5.7 数据库基本信息

设置面板中的数据库基本信息用于维护 `sys_data_asset_map`：

- 展示规则为 `显示名[数据库名]`。
- 没有当前语言展示名时，只显示数据库名。
- 保存应更新同一个 `code` 对应的记录，不能每次保存都新增一行。
- 如果历史数据中存在重复 `code`，系统会优先保留信息更完整的一条并清理重复登记。

## 6. 数据清理

### 6.1 清空单模型数据

在模型信息面板底部可执行：

- 清空该模型对应的业务数据

注意：

- 只清业务行数据
- 不删模型定义
- 不删关系定义

### 6.2 清空整库数据

在设置面板中可执行：

- 清空当前逻辑库中的全部行数据

注意：

- 只清数据
- schema 仍保留

## 7. 常见问题

### 7.1 连不上服务

优先检查：

- host 是否正确
- port 是否正确
- token 是否正确
- 服务端是否启动

### 7.2 打开后没有模型

可能原因：

- 业务库本身为空
- catalog 拉取失败
- 设计器专属库初始化失败

建议先看浏览器控制台和通知中心。

### 7.3 保存后刷新丢失

重点检查：

- 是否真的点击过保存
- 保存时是否报错
- `sys_designer_graph` 是否成功写入
- 是否在刷新前执行了拉取覆盖本地状态

### 7.4 字段或关系显示不完整

可能原因：

- 业务库 catalog 当前只返回了简化字段目录
- 某些字段细节还未在 server catalog 接口中暴露
- 设计器侧历史数据与当前导入逻辑不完全对齐

## 8. 推荐操作习惯

- 每次大改前先拉取一次
- 批量调整后及时保存
- 不要把设计器专属库当业务库使用
- 不要直接手改 `sys_*` 行数据，除非你清楚导入与同步链路

## 9. 数据库备份与恢复入口

模型设计器**右上角工具组**提供当前业务库的管理入口：

- **备份当前库**：调用 server management API 创建备份。
- **恢复当前库**：从主题化列表中选择服务器备份，列表展示文件数量、创建时间和大小；恢复前 server 会尽量创建安全备份。
- **导出备份文件**：选择服务器备份并下载为 `*.modeldb-backup.json`，可用于离线保管或服务器迁移。
- **导入备份文件**：选择本地 `*.modeldb-backup.json`，上传并校验后恢复到当前库；文件会保留在服务器备份目录中。
- **管理清除数据**：清除当前业务库行数据，保留模型和关系定义。
- **强制重置库**：用于数据库文件损坏时的后门恢复，会重建物理库。

这些入口操作的是当前业务库，不是设计器元数据库。恢复、清除、强制重置后，设计器会重新拉取业务库 catalog 并刷新画布。

迁移时建议先在源服务器创建并导出备份，再连接目标服务器、选择目标库并执行“导入备份文件”。备份允许恢复到与源库不同的目标库名称。

## 10. Operation Designer

从右下角“接口管理器”进入 Operation Designer。当前可设计单记录
`create / update / delete / upsert` 和单关系对 `bind / unbind / rebind` 接口：

- 选择目标模型和可写字段，字段会映射为外部调用参数。
- `update / delete` 自动要求调用方传入记录 `id`。
- `upsert` 可将一个或多个写入字段标记为匹配字段；首次调用创建记录，后续相同匹配值更新原记录。
- `bind / unbind` 自动生成 `sourceId / targetId` 参数，并按关系注册顺序定位两端模型。
- `rebind` 自动生成 `sourceId / previousTargetId / nextTargetId`，source 保持不变；新边建立失败时恢复旧边。
- 继承边不可作为业务关系操作目标；发布执行使用稳定的 engine forward/reverse 名称。
- 可配置返回记录、记录引用、操作摘要或无返回值。
- 可使用连接认证、接口专属密钥、停用外部调用和固定窗口限流。
- 保存草稿后在资产页发布；active release 可直接填写参数并通过真实 SDK 链路在线调试。
- 资产页版本台账会显示历史 release 相对当前版本的兼容性级别。选择“回滚到此版本”后，Designer 会先迁移旧契约并重新编译，再发布一个更高的新版本；当前 release 与设计草稿都会保留。

`batch` 将同一种单项操作应用到 `items` 数组。可设置 1-1000 的最大项数，并选择：

- `continue`：单项失败后继续，最终可能返回 `partial`。
- `stop`：首项失败后停止，未尝试项计入 `skippedCount`。

batch 当前是非原子事务：每个成功项会独立提交，不支持跨项回滚。结果摘要固定返回
`status / requestedCount / attemptedCount / successCount / failureCount / skippedCount`；启用逐项结果后，
还会返回带原始索引、成功状态、影响数量、记录引用或结构化错误的 `items`。

## 11. Query Designer：查询链与分页

### 11.1 继承子模型的选择

查询链上，继承子模型和父模型视为同一个节点：

- 已经选择父模型后再选择它的子模型，不会新增节点，而是把当前节点切换为子模型身份，此后可以使用子模型独有的字段和关系。
- 继承连线不会出现在“下一步可选关系”中，点击继承连线等同于选择该子模型。

### 11.2 分页设置

分页设置位于查询路径区域下方，确定查询链（至少选中一个模型）后才显示：

1. 勾选“启用分页”，默认每页 20 条，按偏移量（offset）分页。
2. 在“默认每页数量”中修改每页返回条数。
3. 取消勾选即恢复为不分页（默认状态）。

条件编辑区不再提供分页设置。设计器界面只提供 offset 模式和默认每页数量；cursor 模式和最大每页数量不在这里设置。已有接口如果原本是 cursor 模式，重新勾选“启用分页”会改为 offset。

## 12. 数据透视（Pivot）

数据透视用于查看业务库中的真实数据结果，入口在右下角面板按钮组的“数据透视”按钮（层叠图标），打开后右侧面板会加宽。

### 12.1 选择数据源

- **模型数据**：选择当前业务库中的模型，执行该模型的查询（包含关联数据）。
- **查询接口**：选择已发布的查询接口。只列出带 published release 的接口，非 active 状态的接口不可选。需要参数时在“参数（JSON）”中填写一个 JSON 对象，例如 `{ "id": "..." }`。

点击“执行”后显示结果。执行前必须已打开业务库，否则会提示“当前没有打开业务库”。

### 12.2 查看结果

- **视图**：层级视图按记录展开对象和数组；JSON 视图显示数据源返回的原始行。
- **语言**：`current` 按当前界面语言显示多语言字段，`raw` / `all` 保留原始多语言对象。
- 结果上方显示返回行数和分页模式（未分页 / offset / cursor）。

注意：

- 查询接口的结果只包含接口投影的字段，数据透视不会绕过接口去读取被隐藏的数据库字段。
- release 版本、限流和服务端错误规则在数据透视中同样生效。
- 界面暂无接口专属密钥输入框，配置了专属密钥的接口目前无法在数据透视中调用。
- 当前版本只执行第一页，还不能在界面中翻页。
