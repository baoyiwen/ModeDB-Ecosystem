# 数据导入导出 v1：分阶段执行计划

## 目标与入口

在模型或已发布查询接口的“查看数据”中完成导出、模板填写、预检和后续提交，不增加独立的全局菜单。导出使用真实业务库，不使用设计器专属库作为业务数据源。展示语言只影响表头，完整 I18N 值保留在文件中。

聚合、计算、统计等派生结果仅支持报表导出，不参与回导。关系工作表不依赖 Excel 保护；上传内容必须按当前数据库定义重新验证。

## 阶段与验收

### 1. 模型导出、模板和只读预检（已实现）

- 入口：模型详情 → 查看数据。查询条件、导出 Excel、空白模板与可展开的导入预检直接嵌入 Pivot 全屏预览，不再叠加第二层弹窗。
- 支持当前模型字段的且 / 或条件：等于、不等于、字符串或指定语言文本包含、数值与日期比较 / 范围、为空 / 不为空。相邻的“且”条件先成组，再用“或”连接。默认无条件，未填写完整的条件会阻止查询和导出。
- 条件控件按实时字段类型生成：数字输入、布尔选择、日期时间选择、颜色选择、多语言字段的语言选择和范围起止值；JSON / Unit 暂提供空值检查。
- 预览与导出共用条件与类型校验，条件在数据库执行。编辑后点击“刷新”应用；导出前自动刷新预览，查询失败则停止导出。空白模板不受筛选条件影响，也不需要执行预览查询。
- 切换数据源时隔离模型条件、导入报告和异步结果。预览仍只显示当前返回的样本，导出读取全部匹配记录；并发数据变更时两次查询不保证同一事务快照。
- Excel 第一张表是说明与模型目录，每个模型使用唯一名作为 sheet 名；超过 Excel 命名限制时生成安全名称，并保留映射。
- 当前 UI 每次处理一个模型。默认导出业务字段、原始 ID、完整多语言值，以及触及当前记录的关系。可取消“包含关系数据”，保留空关系表；这不表示回导时删除原有关系。关联模型只输出引用 ID，不自动导出其业务字段。
- 当前支持直接模型端点关系。包含关系时，遇到需要从父模型端点继承的关系，会明确终止导出，避免丢失关系；继承端点的回导映射将在后续阶段补齐。
- 下载空白模板；上传系统导出的文件或填写后的模板，进行只读预检。
- 校验当前模型、字段类型、设计器可用的必填元信息、文件内重复 ID / 行标识、关系双向名称与端点、引用存在性、自环策略、重复关系。
- 按模型去重、分批查询数据库 ID，一次任务共享存在性索引，不对每一行发请求，也不把引擎查询缓存当作写入依据。
- 反馈新增候选、已存在 ID、关系及问题数量；问题定位到工作表、行和字段，可下载 JSON 报告。页面显示前 200 个问题，报告包含全部。
- 文件上限 20 MB、数据 10,000 行、关系 50,000 条。超过限制终止，不截断。普通单元格仅接受值，不接受公式、超链接、富文本。
- 预检不会新增、更新或绑定记录。通过预检只表示本阶段检查通过，不等同于引擎提交成功。已有 ID 只计数，不视为默认覆盖授权。

验收：Excel 往返无损、空模板零记录、错误定位、多语言键齐全；临时业务库通过真实 SDK 导出、Excel 回读、预检后业务文件哈希保持不变。

本次验证：22 项导入导出用例与 6 项 Pivot 回归通过；类型检查与生产构建通过。页面实测以“晚点分钟数 > 20”导出 14 行、52 条关系，原文件上传预检得到新增候选 0、已存在 ID 14、关系 52、问题 0；该流程未提交数据写入。

内嵌 UI 调整验证：29 项回归、模型设计器类型检查和生产构建通过。隔离 HTTP / SDK 比较了无条件、数值、字符串包含和 AND 条件的预览 / 导出结果。页面实测“晚点分钟数 > 20”预览 14 行；改为“> 25”直接导出，自动刷新为 12 行，Excel 导出 12 行、36 条关系，同页预检已有 ID 12、问题 0。展开预检时仍只有一个弹窗；空条件值会阻止查询及数据导出。

检查范围：模型设计器类型检查、data-kit 构建和新模块 lint 通过。根级类型检查仍存在已有 Pivot 引入的 `ImportMeta.env` 类型缺失，以及旧测试文件中的未使用变量错误；本阶段没有修改这些文件来消除提示。Vite 构建仍提示较大的现有主包与 ExcelJS 包，ExcelJS 已按需加载。

### 2. 模型导入提交（下一阶段）

1. 新增导入计划：区分新记录和已存在记录，默认不覆盖；显式选择已有记录处理方式。
2. 提交前重新验证当前 schema、ID 和关系约束，补齐引擎级唯一性、基数与权限检查，处理预检之后数据库变化的情况。
3. 先保存记录并建立 `_key → 实际 ID` 映射，再解析关系；使用 SDK / EngineOperation 提交，不在 React 中拼写入补丁。
4. 明确原子事务、部分成功、取消及重试契约。无法提供原子性时明确返回逐项结果，不显示虚假的“全部回滚”。
5. 输出真实新增 / 更新 / 跳过 / 失败数量、生成 ID、关系结果和可下载报告。

验收：新记录、明确更新、混合输入、前向引用、自关联、提交冲突、失败重试和事务故障注入；隔离库验证，禁止用用户现有业务数据做破坏性实验。

### 3. Query Designer 接口导出

1. 从接口定义生成参数表单，沿用 release、访问密钥、权限、限流和预设条件。已接入 Pivot 接口预览：类型化表单、必填 / 默认值 / 格式校验、专属密钥、固定条件与嵌套 AND / OR / 关联条件 / HAVING 展示均已实现。
2. 只使用接口投影的模型字段，不补查隐藏字段；回导所需身份若不可用，则标记为只读报表。
3. 原始实体按模型分 sheet，原始 ID 去重；单独保存查询路径和出现位置，表达同模型多路径、多级嵌套和自关联。
4. 派生结果以报表导出，明确不可回导。

验收：多模型、多路径、自关联和混合派生结果；导出不越过接口投影。

当前结果导出已接入：接口 Pivot 内提供导出、非聚合接口的空白模板、只读预检与反馈。导出前按当前参数刷新，直接转换该次接口结果；分页接口仅导出当前页，未实施自动遍历所有分页。实体按模型分 sheet、按返回的 ID 去重，关系按真实方向输出，`_paths` 保留每次查询出现路径。无 ID 或聚合结果标为 report 并拒绝回导，不补查隐藏 ID 或字段。导入预检验证来源发布版本、投影字段、关系范围、路径、实时 schema 与 ID；正式提交与完整路径导入编排仍在后续阶段。

接口导出和空模板的字段类型来自实时业务库 catalog，字段范围仍由发布投影决定，避免画布缓存中的旧类型导致新模板自检失败。本轮 44 项相关回归、模型设计器类型检查、data-kit 构建与生产构建通过。页面实测 `Test Query API` 导出当前 100 条根结果及关联数据，当前服务未返回原始记录 ID，因此文件明确标为只读报表；该报表上传会被拒绝回导，新下载空模板预检为 0 行、0 问题。关闭数据页会回到原接口卡片并保持查询设计器；700px 窗口验证了可见横向 / 纵向滚动条及后续列访问。

参数预览验证：15 项 Pivot 回归通过；隔离 HTTP / SDK 实验验证数字 0、布尔 false、服务端默认值、密钥与指定版本、投影限制，业务库文件哈希未改变。现有业务接口 `activeTrainServicesByLine` 在页面中显示固定条件“状态编码不等于 COMPLETED”，自动返回 75 行并保持默认表格。现有两个接口都没有调用参数，参数输入转换另由单元与隔离 HTTP 测试覆盖。

### 4. 接口模板与多模型回导

1. 从可回导的接口定义生成空白模板、关系填写说明与字段约束。
2. 复用模型导入计划和 ID 映射，新增路径一致性与接口字段权限验证。
3. 关系表改动逐条验证，拒绝非法模型、方向、名称、引用和不允许的关联；不执行任意 Excel 公式。

验收：合法模板可导入，篡改关系、丢失身份、未知字段和 schema 漂移给出可定位反馈。

### 5. 任务体验、性能与收尾

完善大文件任务与分页/流式能力、进度、重试、审计、可观测性和三语言文案。存在性缓存限定任务生命周期；提交始终重新验证。性能实验以真实行数和关系数量报告耗时，不以缓存命中替代正确性验证。

## Excel 文件契约 `modedb.transfer.v1`

| 工作表               | 内容                                                                  |
| -------------------- | --------------------------------------------------------------------- |
| 本地化说明与模型目录 | 来源图谱、导出时间、用途、说明、模型与 sheet 映射、行数               |
| 模型唯一名           | 第 1 行可读表头；第 2 行隐藏机器字段；第 3 行起数据                   |
| `_relations`         | `source,target,forward,reverse,sourceRef,targetRef`，可见且不依赖保护 |
| `_paths`（接口文件） | 默认隐藏，保留 `path,parentPath,nodeId,model,key` 及父级路径          |
| `_modedb`            | 隐藏格式元信息、字段类型和模型映射，不作为数据库规则的权威来源        |

模型数据前两列为 `_key`（默认隐藏）和 `_id`。`_key` 在模型内唯一，用于 `row:<key>` 引用；`_id` 始终为文本，用于 `id:<ID>` 引用。新记录可以不填 `_id`。空单元格表示未指定，`\N` 表示 null，`\E` 表示空字符串；原始字符串以反斜杠开头时增加一个反斜杠转义。I18N、JSON、Unit 用 JSON 保存。DateTime 使用 `yyyy-mm-dd hh:mm:ss` 形式的文本，保留原始毫秒和时区，回读时恢复 ISO 分隔符，不丢失时间精度。隐藏机器字段仍可编辑，但不允许缺失、重复、未知列或未归属列的数据被静默丢弃。

模型和关系页均提供 Excel 结构化表格、筛选、冻结表头、明确边框和隔行底色。字段表头按当前语言解析，缺少翻译时保留唯一名；空模板用浅黄色标识待填写区域。

结构化表格独占其范围的筛选定义，不叠加工作表级筛选，避免 Excel 打开时修复并删除表格。表头按 Excel 规则限制为 255 字符并忽略大小写消除重名；完整字段标签仍在元数据中保留。`_modedb` 使用 `kind,json,part,parts` 分块保存 JSON，每块至多 32,000 字符，Unicode 以 JSON 转义保留，读取时严格检查分块顺序和完整性，并兼容旧版两列元数据。接口的完整发布签名不会因单元格上限而被截断。真实业务值超过 Excel 单元格限制时中止导出，页面直接给出工作表、行、单元格和长度。

文件兼容性回归覆盖超长发布签名、完整多语言元数据、反斜杠与 Unicode 边界、旧元数据格式、损坏分块、合法表头和单元格超限定位。真实 `AdministrativeDivision_Query v0.2.0` 的发布签名为 39,228 字符，现可成功导出 17 条模型记录和 16 条关系；下载文件的四个模型表及关系表均保留结构化表格且没有重叠的工作表筛选。实际空模板能完整回读，独立工作簿读取器也能解析新导出文件。Excel 桌面端是否不再触发修复仍需原生打开复核。

日期范围 / 等值比较和指定语言字段查询需要本次引擎修复。已经运行的服务必须正常重启以加载新构建；前端热更新不会替换长驻服务中的引擎模块。隔离 HTTP / SDK 实验覆盖这些条件与模型 / 接口分页，验证过程不写入现有业务库。

展示与条件优化验证：72 项相关回归、模型设计器类型检查和生产构建通过。真实页面验证中文表头、日期格式、模型分页 / 跨页序号 / 页大小切换和数值条件；“晚点分钟数 > 20”返回 14 行，含关系导出 52 条关系，不含关系导出 0 条关系。实际下载文件检查到结构化表格、中文表头、四边框和隐藏辅助键；700px 窗口验证条件控件换行。引擎日期 / 指定语言条件另由隔离服务验证，现有长驻 9091 服务需重启后生效。

本格式不是签名或防篡改机制。校验以最新业务库 catalog 为准，文件内声明不能创建模型、字段或关系。完整的数据库约束检查与正式写入在阶段 2 接入。

## 实现位置与验证

- `packages/data-kit/src/transfer/`：格式、纯验证和反馈契约，无 React / DOM。
- `src/data-transfer/workbook.ts`：应用现有 ExcelJS 生成与读取 Excel。
- `src/data-transfer/model-transfer.ts`：查询、关系收集和分批存在性读取，可注入只读客户端测试。
- `src/data-transfer/execute.ts`：新鲜 catalog 与短生命周期业务会话。
- `src/data-transfer/filters.ts`：模型预览与导出共用的条件转换和类型验证。
- `src/data-transfer/interface-transfer.ts`：已发布接口投影转换、模型去重、关系与查询路径、接口范围校验。
- `src/components/ModelQueryFilters.tsx`、`DataTransferPanel.tsx`：Pivot 内嵌条件、数据操作、进度和报告下载。
- `test/unit/data-transfer.test.ts`、`test/unit/data-transfer-http.test.ts`：格式、校验及隔离 HTTP / SDK 实验。

运行 `pnpm run test:data-transfer`；模型设计器还需运行 `pnpm --filter model-designer typecheck` 和构建。
