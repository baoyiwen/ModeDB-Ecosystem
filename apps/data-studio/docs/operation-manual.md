# Data Studio 操作手册

## 1. 使用前准备

需要先确认：

- `@mode-db/server` 已启动
- 已知 `host / port / connectToken`
- 至少存在一个可用逻辑库

## 2. 启动方式

在仓库根目录执行：

```bash
pnpm --filter data-studio dev
```

打开 Vite 地址后会先进入连接页。

## 3. 连接流程

### 3.1 输入连接参数

填写：

- host
- port
- token

点击连接后，前端会先调用 `listDatabases` 列出逻辑库。

### 3.2 打开逻辑库

从下拉中选择目标逻辑库后点击打开，系统会：

1. 建立远程客户端连接
2. 读取 catalog
3. 进入工作区

## 4. 工作区常见操作

### 4.1 切换模型

顶部模型下拉用于切换当前模型；切换后：

- 表格查询快照会重建
- 透视维度会重置
- 导入面板目标模型会变化

### 4.2 切换视图

可切换：

- 表格
- 透视
- 导入

如果当前存在未提交修改，切换会被阻止并给出提示。

### 4.3 编辑并提交

在表格类视图中修改后，改动会先进入 staging。

点击工具栏提交后，系统会：

1. 将 staged operation 聚合
2. 通过 `applyAll` 提交到 engine
3. 刷新查询结果
4. 给出成功 / 失败提示

### 4.4 导入数据

导入页支持：

- 字段映射
- 类型转换
- 清洗规则
- 关系绑定辅助
- upsert 导入，默认优先建议 `id`、`code`、`key` 等稳定字段

提交导入后会显示写入结果、失败条数与必要提示。

关系绑定注意：

- 匹配字段来自当前 catalog 的模型字段；如果模型有继承父模型字段，Data Studio 会合并父级字段。
- 关系名可能只在两个端点模型之间局部唯一，因此导入绑定会同时参考关系名、导入模型和对端模型。
- 自关联关系需要明确导入行位于 source 侧还是 target 侧；默认按 target 侧处理。
- 如果关系未开启“允许自己绑定自己”，导入时会跳过 `sourceId === targetId` 的直接自环。

### 4.5 显示名模式

Data Studio 支持在展示名和唯一名之间切换：

- 显示名模式：优先显示当前语言下的展示名，并格式化为 `显示名[唯一名]`。
- 唯一名模式：只显示稳定唯一名。
- 该规则适用于数据库、模型、字段、导入面板和 Pivot 表列。
- 如果当前语言没有展示名，则直接显示唯一名。

字段展示名来自 catalog 的 `fieldLabels`。如果 Pivot 或导入面板仍显示默认字段名，优先检查 management catalog 是否返回了正确的 `fieldLabels`。

## 5. 常见问题

### 5.1 连不上服务

检查：

- token 是否正确
- server 是否启动
- 端口是否一致

### 5.2 没有模型可选

可能原因：

- 目标逻辑库 catalog 为空
- 管理面 catalog 读取失败

### 5.3 视图切换被拦截

通常说明当前存在未提交编辑；先提交或回退再切换。

## 6. 推荐使用习惯

- 连接成功后先确认模型列表是否符合预期
- 批量修改优先在一个视图内完成后再提交
- 导入前先确认目标模型字段与字段类型

## 7. 数据库备份与恢复入口

Data Studio 顶部工具区提供当前逻辑库的管理入口：

- **备份**：创建当前库备份。
- **恢复**：从当前库已有备份文件恢复；恢复前 server 会尽量创建安全备份。
- **清除数据**：清除当前库行数据，保留 schema / relation。
- **强制重置**：用于数据库文件损坏时重建物理库。

恢复、清除、强制重置后，Data Studio 会重新打开当前会话并刷新 catalog。备份文件位于服务端 workspace 的 `modeldb/backups/`。
